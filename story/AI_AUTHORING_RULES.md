# AI 스토리 작성 계약

이 파일은 AI 에이전트가 장면을 추가하거나 수정할 때 반드시 지켜야 할 규칙이다.

## 절대 규칙

1. `perceived`는 한도윤의 인지이며 사실이 아니다.
2. `reality`만 실제 대사, 표정, 속마음과 의도를 기록한다.
3. 플레이어 선택 문구, 한도윤의 해석, 실제 행동을 각각 `label`, `interpretation`, `action`으로 분리한다.
4. 수치 변화는 `effects`에만 작성한다. 대사나 설명에 암묵적인 수치 변화를 숨기지 않는다.
5. 조건과 효과가 사용하는 모든 경로는 장면의 `state_contract`에 선언한다.
6. 새 표정 ID를 장면에서 즉석 생성하지 않는다. 캐릭터의 `expressions`에 먼저 등록한다.
7. 인물의 나이, 직급, 말투, 감정 반응은 캐릭터 파일을 우선한다.
8. 의심도가 낮아져도 비호감도가 자동으로 낮아지지 않는다.
9. 호감도는 실제 애정이 아니라 한도윤의 자기확신이다.
10. `밀기`, `당기기`, `중립`은 실제 여성의 감정이 아니라 한도윤의 판정이다.
11. 증거는 구체적인 장면 사건으로만 증가한다. 이유 없이 숫자만 올리지 않는다.
12. 선택지마다 최소 하나의 실제 결과가 있어야 한다. 문구만 다른 동일 선택지는 만들지 않는다.
13. 엔딩이나 외부 장면으로 나가는 모든 분기에는 조건 없는 기본 전이가 있어야 한다.
14. 피해자의 외모나 의상을 피해 원인처럼 서술하지 않는다.
15. 범죄 장면은 방법을 상세히 재현하지 않고 결과와 피해자의 일상 손실을 중심으로 기록한다.
16. 새 장면은 반드시 `events/`의 시간 이벤트에 연결하고 발생 기간·시간대·마감을 정한다.
17. 플레이어가 보지 않은 사건도 필요하면 `availability: hidden` 오프스크린 사건으로 진행시킨다.
18. 특별한 환청·기억 왜곡 연출이 아니라면 들리는 대사의 사실관계는 두 레이어에서 유지한다. 반전은 표정, 생략된 맥락, 속마음과 주인공 해석으로 만든다.
19. 재플레이 보상은 더 심한 가해의 성공이 아니라 진실, 기록 연결과 피해자 대응 선택의 확장으로 설계한다.
20. 장면 YAML에 이미지 파일 경로를 직접 넣지 않는다. 장소·시간·분위기로 `visuals/` 객체가 선택되게 한다.
21. 새 캐릭터는 `character_archetype`을 상속하는 구체 비주얼 객체를 정확히 하나 가져야 한다.
22. 번역문은 한국어 원문을 덮어쓰지 않고 `locales/<locale>.yaml`의 안정 키에 추가한다.
23. 생존 모드의 위험 축은 수치 게이지로 노출하지 않고 한도윤의 행동·말투·접촉 변화로 추론하게 한다.
24. 생존 모드의 실패를 피해자가 폭력을 유발한 결과로 서술하지 않는다. 폭력의 책임은 항상 가해자에게 있다.
25. 생존 모드의 핵심 자원은 증거, 신뢰할 수 있는 연결, 타이밍이다. 가해를 회피하거나 은폐하는 재현 가능한 방법을 보상으로 작성하지 않는다.
26. 생존 모드는 본편과 동일한 날짜·시간대·핵심 사건을 피해자의 `reality` 시점으로 되짚는다. 대사와 핵심 사실을 본편과 모순되게 바꾸지 않는다.
27. 한도윤은 생존 모드에서 초반부터 지속적으로 공격적이다. 이 공격성을 피해자의 선택이 만든 것처럼 쓰지 않는다.
28. 플레이어의 핵심 선택은 한도윤을 최대한 자극하지 않으면서 이미 벌어지는 행동의 물리적 증거를 확보·보존하는 것이다. 증거를 위해 폭력을 직접 유도하는 선택은 만들지 않는다.

## 장면 작성 절차

1. `python3 tools/story_harness.py context --scene <ID> --from-route <ROUTE> --choose <PREVIOUS_SCENE>=<OPTION>`으로 해당 분기 상태가 반영된 컨텍스트를 생성한다. 진입 장면이라 이전 선택이 없을 때만 `--from-route`를 생략한다.
2. 장면의 목적을 한 문장으로 정한다.
3. 필요한 상태 읽기·쓰기를 먼저 선언한다.
4. 실제 사건과 실제 감정을 `reality`에 먼저 작성한다.
5. 같은 사건을 한도윤이 어떻게 연애 서사로 편집하는지 `perceived`에 작성한다.
6. 선택지의 실제 행동과 상태 효과를 연결한다.
7. 새 장소라면 모든 노드의 두 모드에 배경이 해석되는지 확인한다.
8. `validate`로 참조·계약·비주얼·locale fallback·도달 가능성을 검사한다.
9. `simulate`로 최소 두 선택 경로를 확인한다.
10. `timeline`으로 장면을 호출하는 사건의 발생 가능성과 놓침 결과를 확인한다.
11. `build`로 런타임 JSON을 갱신한다.

## 에이전트 응답 형식

장면을 제안할 때는 다음 순서를 사용한다.

1. 장면 목적
2. 진입 상태
3. 실제 사건
4. 한도윤의 인지
5. 선택지와 수치 변화
6. 다음 분기
7. 수정한 파일
8. 검증 결과

불확실한 설정은 임의로 확정하지 않고 `open_questions`에 기록한다.
