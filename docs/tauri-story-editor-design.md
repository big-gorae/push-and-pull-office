# Tauri 스토리 에디터 설계

## 1. 목표

제작자가 `story/**/*.yaml`의 구조와 점 표기 상태 경로를 외우지 않아도 다음 작업을 GUI에서 수행할 수 있게 한다.

- 루트, 장면, 노드의 관계를 탐색한다.
- 15일 시간표에서 언제 누구를 만나고, 만나지 않은 동안 무엇이 벌어지는지 확인한다.
- 특정 수치와 회차 상태에서 사건이 열리거나 막히는 이유를 시뮬레이션한다.
- 본편의 왜곡된 대사와 실제 대사·속마음을 나란히 수정한다.
- 선택지의 조건과 수치 효과를 드롭다운과 숫자 입력으로 구성한다.
- 수치를 움직여 어떤 표정, 대사, 선택지와 다음 장면이 표시되는지 즉시 확인한다.
- 저장 전에 스키마, 참조, 상태 계약, 도달 가능성과 표현 레이어를 검증한다.
- 잘못된 편집이나 외부 파일 변경이 있어도 원본 YAML을 잃지 않는다.

에디터의 최종 목적은 YAML을 없애는 것이 아니다. YAML은 계속 버전 관리 가능한 원본이고, GUI는 YAML을 안전하게 생성·수정·검증하는 제작 도구다.

## 2. 제품 범위

- 3막·15일·4개 시간대 타임보드
- 회사·인물·오프스크린·과거 사건 스윔레인
- 주인공 인식 / 실제 시간선 전환
- 사건 발생 기간·마감·우선순위·조건·효과 편집
- 놓친 사건과 자동·hidden 사건 실행 시뮬레이션
- 루트·장면·노드 탐색기
- 장면 기본 정보 편집
- 6종 노드 편집
- 이중 레이어 대사 편집
- 조건·효과 빌더
- 상태 계약 자동 계산
- 실시간 게임 화면 미리보기
- 현재 수치에 따른 분기 판정 표시
- 장면 단위 Undo/Redo
- 임시 초안 복구
- 전체 검증 후 안전 저장
- 런타임 JSON 재빌드
- 기존 콘셉트 아트 미리보기
- 한국어·영어 locale 전환, fallback과 번역 누락률
- 인물 프로필, 말투, 표정, 감정·신고 규칙과 관계의 구조화 편집
- 장면 복제 시 연결 시간 사건과 루트·스레드 순서를 하나의 검증 트랜잭션으로 생성
- 사건 복제 시 사건 YAML과 소속 스레드 순서를 함께 생성하고 실패 시 전체 롤백
- 장소·시간·분위기별 배경 자동 해석과 16:9 무대 프리뷰
- 배경·캐릭터 원형 상속과 의상·포즈·표정 합성 슬롯 탐색

### 2.2 이후 버전으로 미룸

- 자유 배치형 노드 그래프 편집
- 번역 키의 대량 표 형태 편집과 CAT 도구 연동
- 실제 게임 엔진 실행
- 이미지 크롭·보정 같은 아트 제작 기능
- Git 커밋·푸시 자동화
- 여러 사람이 동시에 같은 장면을 편집하는 협업 기능

첫 버전의 그래프는 읽기와 선택 전용이다. 노드 추가·삭제·순서 변경은 구조화된 목록과 폼으로 처리한다. 자유 배치 캔버스는 편해 보이지만 연결선 편집, 레이아웃 저장, 키보드 접근성 때문에 구현량이 크게 늘어난다.

## 3. 제작자 관점의 핵심 원칙

1. **원문 필드명을 기본 화면에서 숨긴다.**
   `hidden.heroines.yoon_seo_a.suspicion` 대신 `윤서아 / 의심도`를 보여준다.

2. **왜곡과 현실을 항상 같은 화면에서 편집한다.**
   한쪽 레이어를 빼먹을 수 없게 두 열을 한 편집 단위로 취급한다.

3. **조건의 순서가 곧 우선순위임을 시각화한다.**
   위에서 먼저 충족되는 분기에 `우선 적용` 표시를 준다.

4. **수치 변경 결과를 저장 전에 실행한다.**
   선택지 효과를 적용한 이후의 값과 도달 노드를 미리 보여준다.

5. **구조적 오류가 있는 원본은 만들지 않는다.**
   편집 중 오류는 허용하지만, 소스 저장은 오류가 0개일 때만 허용한다.

6. **ID는 별도 고급 작업으로 취급한다.**
   배포된 ID 변경이 세이브 호환성을 깨뜨리므로 일반 텍스트처럼 수정하지 않는다.

7. **시간표는 화면의 주축, 이벤트 풀은 문서의 주축으로 둔다.**
   제작자는 날짜별 화면에서 편집하지만 원본은 날짜 파일로 복제하지 않고 발생 범위를 가진 사건으로 보관한다.

8. **보이지 않는 시간도 진행시킨다.**
   플레이어가 사건을 놓치면 상담, 기록 공유와 과거 조사 같은 실제 사건이 별도 레인에서 발생한다.

9. **저장은 기능이 아니라 항상 보이는 상태다.**
   입력 중, 검증 중, 디스크 저장 완료, 충돌·오류를 현재 YAML 경로와 함께 표시한다. 장면·이벤트·인물·번역·프로젝트 설정은 입력을 멈추면 자동 저장하고, 앱이 닫히기 전에는 복구용 초안을 별도로 보관한다.

10. **찾기는 파일 구조보다 빠르다.**
    `⌘P`에서 장면 제목·목적·대사, 시간 이벤트의 두 시점 설명, 인물, 캠페인, 루트, 스레드, 해금과 비주얼 객체를 함께 검색한다. 결과를 열면 담당 편집 화면의 해당 문서로 직접 이동한다.

11. **시간 구조와 자산 규칙도 YAML 없이 수정한다.**
    `구조·자산` 작업공간에서 전체 날짜·시간대·막·레인, 사건 스레드 순서, 루트 순서·엔딩·해금, 클리어 후 예고, 배경 판정 variant와 인물 이미지 구성을 편집한다. 모든 변경은 다른 문서와 함께 전체 검증을 통과한 뒤에만 원본에 기록한다.

## 4. 기본 시간 설계 화면

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ [시간 설계] [장면·대사]   검증 0 오류                 런타임 빌드       │
├───────────────┬────────┬────────┬────────┬────────┬──────────────────────┤
│ 시간선        │ 1일    │ 2일    │ 3일    │ 4일    │ 사건/수치 시뮬레이터 │
├───────────────┼────────┼────────┼────────┼────────┤                      │
│ 회사          │ 고정   │        │        │ 보고   │ 날짜·시간대 실행     │
│ 윤서아        │        │ 점심   │ 점심   │ 인사   │ 발생/차단 이유       │
│ 차민경        │        │        │ 퇴근후 │ 퇴근후 │ 이벤트 편집·저장     │
│ 보이지 않는 일│        │        │        │ 상담   │ 인물 수치 슬라이더   │
└───────────────┴────────┴────────┴────────┴────────┴──────────────────────┘
```

- 5일씩 한 주를 보여 주어 15일 전체를 세 화면으로 탐색한다.
- 주인공 인식에서는 truth 레인을 숨기고, 실제 시간선에서는 같은 날짜에 겹쳐 표시한다.
- 사건 카드는 발생 가능, 조건 미충족, 예정, 발생 완료, 놓침을 색과 문구로 함께 구분한다.
- 카드를 선택하면 연결 장면을 열거나 이벤트 YAML을 바로 수정한다.

## 5. 장면·대사 화면

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 프로젝트명   검증 0 오류 · 초안 저장됨                 빌드   소스 저장 │
├───────────────┬──────────────────────────────────────┬───────────────────┤
│ 스토리 탐색기 │ 편집기                               │ 라이브 미리보기  │
│               │                                      │                   │
│ 캐릭터        │ [장면] [노드] [조건/효과]            │ 본편 / 실제 원문 │
│ 루트          │                                      │ 표정·대사·HUD    │
│  └ 장면       │ 선택한 항목의 구조화된 폼            │                   │
│     └ 노드    │                                      │ 상태 슬라이더    │
│ 엔딩          │                                      │ 현재 분기 판정   │
├───────────────┴──────────────────────────────────────┴───────────────────┤
│ 검증 서랍: 오류/경고 · 파일 · 필드 · 바로 가기                         │
└──────────────────────────────────────────────────────────────────────────┘
```

권장 기본 비율은 탐색기 20%, 편집기 48%, 미리보기 32%다. 창 폭이 좁으면 미리보기는 오른쪽 패널이 아니라 탭으로 이동한다.

### 5.1 연출·번역 화면

세 번째 작업 공간은 장면 텍스트와 자산을 직접 결합해 보여 준다.

- locale 선택 시 번역이 있는 문장만 교체하고 나머지는 기본 한국어로 fallback한다.
- 장면과 노드를 고르면 `location`, `time`, 현재 레이어의 `atmosphere`로 배경 variant를 결정한다.
- 출연진은 캐릭터 비주얼 객체의 기본 의상·포즈와 노드 표정을 합성한다.
- flat portrait 단계에서는 콘셉트 아트를 안전한 fallback으로 쓰며, layered sprite가 생기면 객체의 렌더 전략만 교체한다.
- 우측에는 locale 직접 번역률, 누락 키, `extends` 계층과 최종 배경 판정 근거를 표시한다.

## 6. 정보 구조

### 6.1 왼쪽 탐색기

탐색기는 파일 경로가 아니라 게임의 구조로 묶는다.

```text
캐릭터
  윤서아
  차민경
  강유진

루트
  말하지 못한 거절
    자료는 메일로
      request             이중 대사
      interpret           선택지
      after_choice        이중 대사
      leave               장면 이탈
    다시 웃었다
  명확한 선
  원문 고정

엔딩
  서아 · 완벽한 간격
  서아 · 말한 적이 없다는 말
```

각 항목에는 오류 상태만 작은 아이콘으로 표시한다. 파일명, 스키마 버전과 원본 경로는 `고급 정보`에서 확인한다.

### 6.2 중앙 편집기 탭

- `장면`: 제목, 목적, 장소, 시간, 출연진과 시작 노드
- `노드`: 선택한 노드 종류에 맞는 폼
- `조건/효과`: 선택지·게이트·이탈의 판정 규칙
- `원본 YAML`: 고급 사용자용 읽기/편집 탭

원본 YAML 탭의 변경도 같은 검증 파이프라인을 통과한다. 폼과 원본을 동시에 바꿀 경우 마지막 정상 파싱 결과를 기준으로 동기화한다.

### 6.3 오른쪽 라이브 미리보기

기존 `editor/`의 미리보기 기능을 재사용한다.

- 본편 / 실제 원문 전환
- 호감도, 주도권, 현재 해석
- 의심도, 비호감, 물리적 증거
- 파생 감정·행동·기본 표정
- 현재 대사·속마음·의도
- 조건에 의해 노출되는 선택지
- 현재 게이트와 이탈 분기의 판정 결과

미리보기의 수치 변경은 편집 대상 YAML을 바꾸지 않는다. 별도의 `테스트 상태`이며 장면을 바꿔도 유지하거나 초기 상태로 되돌릴 수 있다.

## 7. 노드별 편집 화면

### 7.1 이중 대사 `dual_dialogue`

```text
화자: [윤서아 ▼]

┌─ 주인공이 보는 장면 ─────────┬─ 실제 장면 ───────────────────┐
│ 분위기  [warm_romance ▼]     │ 분위기  [guarded_office ▼]   │
│ 표정    [수줍음 ▼]           │ 표정    [긴장 ▼]             │
│ 대사    [                   ] │ 대사    [                   ] │
│ 해석    [                   ] │ 속마음  [                   ] │
│                               │ 의도    [boundary ▼]          │
└───────────────────────────────┴───────────────────────────────┘

다음 노드: [interpret ▼]
```

- 표정 목록은 선택한 화자의 캐릭터 파일에서 가져온다.
- 주인공 열에는 `perceived` 레이어 표정만, 실제 열에는 `reality` 레이어 표정만 표시한다.
- 잘못된 레이어의 표정은 목록에 나오지 않는다.
- 두 대사의 차이가 너무 작거나 완전히 같아도 오류는 아니며, 비교 표시만 제공한다.

### 7.2 이중 내레이션 `dual_narration`

화자와 표정이 없고, 두 레이어의 분위기·문장·해석·속마음·의도만 편집한다.

### 7.3 선택지 `choice`

```text
질문: 다시 당겨 온 서아에게 어떻게 반응할까?

선택지 1  그녀의 용기에 답한다
  주인공 해석: 당기기 신호를 놓치지 않는다.
  실제 행동:   퇴근 뒤 둘만의 식사를 제안한다.
  표시 조건:   없음
  수치 효과:   호감도 +15 / 의심도 +25 / 증거 +1
  다음 노드:   leave
```

- 선택지는 위아래로 재정렬할 수 있다.
- `플레이어 문구`, `주인공 해석`, `실제 행동`을 서로 다른 필드로 유지한다.
- 조건에 맞지 않는 선택지는 미리보기에서 잠금 처리하지 않고 기본적으로 숨긴다. 에디터의 디버그 옵션에서만 `숨겨진 선택지 표시`를 켤 수 있다.

### 7.4 수치 분기 `state_gate`

```text
1순위  [윤서아] [의심도] [이상] [20]  → guarded_smile
기본   위 조건이 모두 거짓             → relief_smile
```

- 순서를 드래그 또는 위/아래 버튼으로 바꾼다.
- 각 분기에 현재 테스트 상태의 `충족` 또는 `미충족` 표시를 준다.
- 실제로 선택된 첫 번째 분기를 강조한다.
- 기본 분기는 항상 마지막 하나만 허용한다.

### 7.5 상태 효과 `effect`

조건 없이 발생하는 상태 변경 목록과 다음 노드를 편집한다. 조건부 효과는 각 효과 행을 펼쳐 조건을 추가한다.

### 7.6 장면 이탈 `exit`

`state_gate`와 동일한 조건 빌더를 쓰되 목적지가 다른 장면 또는 엔딩이다. 장면 선택 목록은 현재 루트의 장면을 먼저 보여주고 다른 루트는 고급 목록으로 분리한다.

## 8. 조건 빌더

제작자가 상태 경로와 연산자 이름을 외우지 않게 한다.

```text
[대상 인물: 윤서아 ▼]
[수치: 의심도 ▼]
[비교: 이상 ▼]
[값: 20]
```

GUI 선택은 내부적으로 다음 YAML로 변환된다.

```yaml
- path: hidden.heroines.yoon_seo_a.suspicion
  op: gte
  value: 20
```

### 8.1 UI 용어 매핑

| GUI | 내부 경로·연산 |
|---|---|
| 호감도 | `visible.heroines.<id>.affection` |
| 밀당 주도권 | `visible.heroines.<id>.initiative` |
| 현재 해석 | `visible.heroines.<id>.perceived_state` |
| 의심도 | `hidden.heroines.<id>.suspicion` |
| 비호감 | `hidden.heroines.<id>.dislike` |
| 물리적 증거 | `hidden.heroines.<id>.evidence_count` |
| 같다 / 다르다 | `eq` / `ne` |
| 초과 / 이상 | `gt` / `gte` |
| 미만 / 이하 | `lt` / `lte` |
| 포함 / 미포함 | `contains` / `not_contains` |

필드 타입에 맞는 연산자만 보여준다. 숫자에는 범위 비교, 배열에는 포함 비교, 선택형 값에는 같음 비교만 제공한다.

## 9. 효과 빌더

```text
[대상 인물: 윤서아 ▼]
[수치: 의심도 ▼]
[변경: 더하기 ▼]
[값: +25]
```

효과를 추가하면 미리보기에서 다음을 동시에 보여준다.

```text
의심도 12 → 37
비호감 18 → 36
증거 0 → 1
파생 감정 cautious → anxiety
다음 분기 relief_smile → guarded_smile
```

범위를 넘는 숫자는 manifest의 최솟값·최댓값으로 제한된 최종값을 표시한다. 원본 입력값이 지나치게 크면 경고한다.

## 10. 상태 계약 자동 관리

현재 YAML의 `state_contract.reads`와 `writes`는 제작자에게 부담이 크다. GUI에서는 다음처럼 처리한다.

- 조건을 추가하면 해당 경로를 `reads`에 자동 추가한다.
- 효과를 추가하면 해당 경로를 `writes`에 자동 추가한다.
- 더 이상 참조하지 않는 경로는 저장 직전에 제거 후보로 표시한다.
- 기본 화면에는 `이 장면이 읽는 수치 3개 / 바꾸는 수치 6개`처럼 요약한다.
- 고급 탭에서만 실제 경로 목록과 수동 고정을 허용한다.

저장 시 에디터가 계산한 계약과 YAML 계약이 다르면 자동 수정 내용을 diff로 보여준다.

## 11. 분기 시뮬레이션

### 11.1 장면 테스트

현재 장면의 시작 노드부터 실행한다.

1. 테스트 상태 입력
2. `state_gate` 자동 통과
3. 실제 표시될 대사·표정 확인
4. 선택지 선택
5. 효과 전후 값 확인
6. `exit`의 다음 장면 확인

### 11.2 루트 테스트

- 선택 전략: 첫 선택지, 마지막 선택지, 직접 선택
- 특정 장면까지 빠르게 실행
- 선택 기록과 상태 변경 trace 표시
- 도달 엔딩 표시
- 도달하지 못한 장면과 엔딩 표시

### 11.3 경계값 테스트

조건이 `의심도 >= 20`이면 다음 세 상태를 한 번에 검사한다.

- 19: 미충족
- 20: 충족
- 21: 충족

선택한 장면의 모든 숫자 조건에 대해 경계값 테스트를 실행해 예상과 다른 분기를 찾는다.

## 12. 검증 UX

검증 결과는 세 등급으로 구분한다.

- `오류`: 소스 저장 불가
- `경고`: 저장 가능하지만 확인 권장
- `정보`: 자동 정리 또는 제작 참고

오류 예시:

- 필수 reality 레이어 누락
- 화자에게 없는 표정 ID 참조
- 다음 노드 또는 장면 ID가 존재하지 않음
- 기본 전이 누락 또는 중복
- 시작 노드에서 도달할 수 없는 노드
- 조건·효과에 사용한 경로가 상태 계약에 없음

검증 항목을 클릭하면 해당 장면과 필드로 이동한다. 오류 문구에는 YAML 경로보다 사람이 읽는 문구를 먼저 쓴다.

```text
윤서아 · 다시 웃었다 · guarded_smile
실제 표정 `actual_warning`은 윤서아에게 등록되어 있지 않습니다.
```

## 13. 저장과 복구 정책

### 13.1 소스 오브 트루스

- 원본: `story/**/*.yaml`
- 생성물: `build/story-runtime.json`
- 앱 초안: 운영체제의 Tauri AppData
- 이미지: `assets/**`

에디터는 `build/story-runtime.json`을 직접 편집하지 않는다.

### 13.2 저장 순서

```text
폼 변경
  ↓
메모리 초안 자동 저장
  ↓
필드 검증 + 장면 검증
  ↓
프로젝트 전체 검증
  ↓
저장 diff 확인
  ↓
같은 폴더의 임시 파일에 기록
  ↓
임시 파일 재파싱·재검증
  ↓
원본으로 원자적 교체
  ↓
runtime 재빌드
```

### 13.3 YAML 보존

일반 객체로 파싱한 뒤 다시 직렬화하면 주석과 작성 순서가 사라질 수 있다. 따라서 저장 계층은 YAML의 구문 트리와 필드 위치를 유지하는 round-trip 편집 방식을 사용한다.

- 변경된 필드만 구문 트리에 반영
- 기존 주석과 키 순서 유지
- 새 노드는 프로젝트 템플릿 순서로 삽입
- 원본 YAML을 직접 수정한 경우 전체 문서를 다시 파싱해 폼과 동기화

### 13.4 외부 변경 충돌

파일을 열 때 해시를 보관한다. 저장 직전 현재 파일 해시가 달라졌다면 덮어쓰지 않고 다음 선택을 제공한다.

- 외부 변경 다시 불러오기
- 내 초안과 비교
- 충돌 해결 후 저장

### 13.5 Undo와 초안

- 텍스트 입력은 500ms 단위로 한 Undo 작업으로 묶는다.
- 노드 추가·삭제·이동은 각각 한 작업이다.
- Undo/Redo는 장면별로 유지한다.
- 소스에 저장하지 않은 변경은 AppData에 자동 저장한다.
- 앱 비정상 종료 후 프로젝트를 다시 열면 초안 복구 여부를 묻는다.

## 15. Tauri 명령 계약

### 15.1 프로젝트

```ts
type ProjectSummary = {
  root: string;
  projectId: string;
  title: string;
  sourceHash: string;
  counts: { characters: number; routes: number; scenes: number };
};

open_project(): Promise<ProjectSummary>
reload_project(): Promise<ProjectSnapshot>
```

프로젝트 폴더는 사용자가 네이티브 폴더 선택창에서 고른다. 선택 후 Rust가 `story/manifest.yaml` 존재 여부를 확인하고 해당 루트만 세션 범위에 허용한다.

### 15.2 읽기

```ts
get_project_snapshot(): Promise<ProjectSnapshot>
get_scene(sceneId: string): Promise<EditableDocument<Scene>>
get_character(characterId: string): Promise<EditableDocument<Character>>
get_route(routeId: string): Promise<EditableDocument<Route>>
```

`EditableDocument`에는 데이터, 원본 YAML, 파일 상대 경로와 revision 해시가 들어간다.

### 15.3 검증과 시뮬레이션

```ts
validate_draft(input: DraftDocument): Promise<ValidationReport>
validate_project(): Promise<ValidationReport>
simulate_scene(input: SceneSimulationRequest): Promise<SimulationTrace>
simulate_route(input: RouteSimulationRequest): Promise<SimulationTrace>
```

### 15.4 저장과 빌드

```ts
save_document(input: {
  kind: "scene" | "character" | "route";
  id: string;
  revision: string;
  patch: StoryPatch[];
}): Promise<SaveResult>

build_runtime(): Promise<BuildResult>
```

`save_document`는 절대 경로를 받지 않는다. Rust가 manifest의 파일 패턴과 ID 인덱스를 통해 대상 파일을 결정한다.

## 16. 기존 Python 하네스와의 관계

### 16.1 첫 구현

현재 `tools/story_harness.py`를 검증·빌드·시뮬레이션의 기준 구현으로 유지한다.

- Tauri Rust 명령이 프로젝트 내부의 Python 하네스를 실행한다.
- 표준 출력 대신 JSON 결과 모드를 추가해 구조화된 결과를 받는다.
- GUI 자체의 빠른 필드 검증과 미리보기는 TypeScript에서 수행한다.
- 실제 저장 가능 여부는 Python 전체 검증 결과가 결정한다.

이 방식은 기존 14개 테스트를 그대로 활용하고 판정 로직이 두 벌로 갈라지는 위험을 줄인다.

### 16.2 독립 배포가 필요할 때

Python 설치 없이 앱을 배포해야 하는 시점에 다음 중 하나를 선택한다.

1. 하네스를 단일 실행 파일 sidecar로 묶는다.
2. 검증·빌드·시뮬레이션 코어를 Rust 라이브러리로 이식한다.

사내 또는 개인 제작툴 단계에서는 1차 구조로 충분하다. 독립 배포 요구가 확정되기 전에 코어를 전면 이식하지 않는다.

## 17. 권한과 보안

- 최초에는 파일 접근 권한이 없다.
- 사용자가 선택한 프로젝트 루트만 런타임 scope에 추가한다.
- `story/**/*.yaml`, `assets/**`, `build/**`만 읽는다.
- 쓰기는 `story/**/*.yaml`과 `build/story-runtime.json`으로 제한한다.
- `.git/**`, 사용자 홈 전체와 프로젝트 밖 경로는 명시적으로 거부한다.
- 쉘 명령은 임의 문자열을 받지 않고 허용된 하네스 서브커맨드만 실행한다.
- 외부 URL이나 네트워크 접근은 기본적으로 사용하지 않는다.

완료 기준:

### 단계 C: 캐릭터·루트 편집과 제작 편의

- [완료] 캐릭터 표정·감정 규칙 편집

- [완료] 루트 순서·진입·엔딩·해금 조건 편집
- [완료] 모드 해금·다음 이야기 예고와 비주얼 자산 판정 규칙 편집
- 경계값 테스트
- 전체 루트 도달성 보고서
- 장면 복제와 ID 생성 보조

완료 기준:

- 캐릭터, 루트, 장면 YAML의 주요 필드를 모두 GUI로 편집할 수 있다.
- 잘못된 표현 레이어와 끊긴 참조를 저장 전에 잡는다.
- 모든 엔딩의 도달 가능 여부를 한 화면에서 확인할 수 있다.

## 21. 최종 인수 조건

다음 항목이 모두 증명되어야 에디터 설계 목표가 구현된 것으로 본다.

- 제작자가 점 표기 상태 경로를 직접 입력하지 않고 조건과 효과를 만들 수 있다.
- 6종 노드를 모두 GUI에서 생성·수정·삭제·재정렬할 수 있다.
- 본편과 실제 원문을 동시에 편집하고 같은 테스트 상태로 비교할 수 있다.
- 수치 변경에 따라 표정, 감정, 선택지, 게이트와 다음 장면이 즉시 바뀐다.
- 상태 계약은 편집 내용에서 자동 계산된다.
- 잘못된 표정, 참조, 기본 분기와 도달 불가능 노드를 저장 전에 찾는다.
- 외부 파일 변경과 revision 충돌 시 원본을 덮어쓰지 않는다.
- 앱 종료 후 미저장 초안을 복구할 수 있다.
- 저장된 YAML의 기존 주석과 키 순서를 보존한다.
- 저장 직후 `validate`, `build`와 기존 테스트가 모두 성공한다.
- 파일 쓰기 권한은 열린 프로젝트 내부의 허용된 경로로 제한된다.
- 지원 locale의 fallback 순환이 없고, 누락 번역이 기본 언어로 표시된다.
- 모든 장면·노드가 본편과 실제 모드에서 유효한 배경을 얻는다.
- 모든 캐릭터가 정확히 하나의 구체 비주얼 객체를 가지며 원형 상속 결과를 런타임에서 확인할 수 있다.

## 22. 권장 결론

첫 구현은 단계 A와 B를 한 목표로 잡는다. 자유 배치 노드 캔버스와 독립 실행용 코어 이식은 미룬다. 이렇게 하면 현재 문서 관리의 가장 큰 어려움인 상태 경로, 이중 대사, 조건 순서, 상태 계약과 저장 오류를 먼저 제거하면서도 구현 범위를 통제할 수 있다.
