# 웹 미연시 플레이어 설계

## 결정

현재 React + TypeScript + Vite 스택을 유지한다. Phaser/Pixi는 맵, 충돌, 다수 스프라이트처럼 캔버스 장면 관리가 필요해질 때만 선택적으로 추가한다. 현재 게임의 핵심은 2D 일러스트, 대사, 선택지와 상태 분기이므로 DOM 기반 UI가 구현과 에이전트 수정 양쪽에서 가장 단순하다.

편집기와 플레이어는 같은 저장소와 스토리 런타임을 공유하되 진입점을 분리한다.

- 편집기: `/`
- 웹 플레이어: `/play` 또는 `#/play`
- 이야기 원본: `story/`
- 생성 데이터: `build/story-runtime.json`
- 플레이어 실행기: `src/player/`

정적 호스팅에서는 `sites-worker/index.js`가 `/play` 같은 SPA 경로를 `index.html`로 되돌린다. `npm run build:site`는 `VITE_APP_SURFACE=game`으로 빌드해 배포 주소의 루트도 곧바로 게임을 열며, 일반 Vite 산출물과 호스팅 진입점을 함께 준비한다.

다국어 레지스트리, 장면 진입 조건, 상황별 대사 variant와 locale 독립 세이브는 [`localization-context-dialogue-redesign.md`](localization-context-dialogue-redesign.md)의 계약을 따른다.

## 시작 화면

새 게임 화면에는 별도의 `NEW GAME` 소개 헤더나 설명 블록 없이 다음 세 모드 카드만 같은 위계로 배치한다.

1. `스토리 모드`
2. `속마음 모드` — `그녀들의 일상과 속마음을 들어 보아요`
3. `어나더 스토리` — `새로운 그녀로 새로운 이야기를 만들어 보아요`

첫 회차에는 스토리 모드만 열고, 첫 엔딩을 본 직후 속마음 모드와 어나더 스토리를 동시에 연다. 안정 ID는 각각 `base`, `truth_view`, `survivor_view`를 유지한다.

## 플레이 화면

- 배경 위에는 현재 발화자의 일러스트만 표시한다. 비발화 인물은 무대에서 숨기고 `presentation: text_only` 동료에게는 일러스트를 만들지 않는다.
- 하단 대사창은 실제 화자 이름만 표시한다. `dual_narration`은 이름표를 숨기며 `나레이션`이라는 이름을 출력하지 않는다.
- 일반 대사 뒤에 한도윤의 해석이나 실제 속마음을 보조문단으로 붙이지 않는다. `inner_voice` 노드를 다음 발화처럼 따로 재생한다. 현재 레이어 speaker가 인물 ID면 1인칭 속말을 괄호로 표시하고, 명시적 `null`이면 권위적 서술을 괄호와 이름표 없이 표시한다.
- 리듬 막대는 대사창 바로 위 오른쪽에 충분한 폭과 대비로 둔다. 선택 효과의 내부 태그·강도·수치 합산은 디버깅 모드에서만 보여 준다.
- 퀵 메뉴는 백로그, 오토, 읽은 문장 스킵, 저장, 불러오기, 설정과 창 숨기기를 제공한다.
- 클릭·Enter·Space로 진행하고 숫자·방향키로 선택지를 조작한다. Escape/H로 UI를 숨기고 PageUp·휠 올리기로 백로그를 연다.
- 자동 저장 1개와 수동 슬롯 8개를 브라우저 `localStorage`에 보관한다.

## 선택지

`choice.stimulus`를 선택의 원인이 된 직전 말이나 행동의 한 문장 요약으로 먼저 보여 준다. 그 아래 선택 버튼은 둥근 카드 묶음이 아니라 대비가 분명한 직사각형 목록으로 배치한다.

- `label`에는 플레이어가 실제로 말하거나 수행할 행동을 쓴다.
- 미묘한 해석을 선택시키는 경우에도 자연스러운 문장으로 쓰고 `밀기`, `당기기`, `push`, `pull`이라는 제작 판정을 노출하지 않는다.
- 객관적 행동이 같은 선택지를 해석만 달리해 중복하지 않는다.
- 디버깅 모드에서만 각 선택의 `push_pull.action`, 강도와 계산 결과를 덧붙인다.

## 날짜 진행

캠페인 날짜·시간대와 이벤트 큐는 런타임 안에서 유지하지만 플레이어에게 별도의 타임라인이나 ACT 선택 화면을 보여 주지 않는다.

1. 마감이 지난 사건과 오프스크린 사건을 내부적으로 처리한다.
2. 다음 의미 있는 대사 장면까지 자동으로 진행한다.
3. 같은 시각에 선택 가능한 사건이 여럿이면 현재 장면 안의 상황 요약과 선택지로 고르게 한다.
4. 날짜가 바뀔 때만 페이드, 분홍빛 달력과 다이얼을 조합한 짧은 전환 연출을 재생한다.
5. `return_to_timeline`은 호환용 내부 완료 값이며, 실제 화면은 사건 큐를 계산한 뒤 다음 장면으로 곧바로 이어진다.

캠페인 총일수와 ACT 제목은 제작 데이터에만 남기고 타이틀, 로비, 전환 화면과 상시 HUD에서 강조하지 않는다.

## 디버깅 모드

환경설정에서 명시적으로 켤 수 있는 디버깅 모드는 다음 기능을 제공한다.

- 이전 대사로 한 단계 돌아가기
- 선택지의 제작용 밀당 방향·강도와 결과 확인
- 현재 장면·노드·이벤트 ID 확인
- 발화자 일러스트의 X/Y 위치와 크기를 즉시 조절

이전 대화는 전체 세션 스냅샷을 복원해 선택 효과와 상태도 함께 되돌린다. 캐릭터 배치값은 제작 설정으로 저장하며 장면 YAML에 임시 좌표나 자산 경로를 복제하지 않는다.

## 일러스트 호흡 연출

기본 연출은 GIF나 리깅 없이 정지 이미지 전체에 매우 작은 세로 스케일과 위치 변화를 약 5.8초 주기로 적용한다. 움직임 줄이기를 켜면 정지한다.

이 방식은 가볍고 모든 PNG/WebP에 바로 적용할 수 있지만, 머리카락·눈·입·가슴을 서로 다르게 움직이지는 못한다. 그런 부분별 움직임이 필요해질 때만 별도 레이어 PSD/PNG 또는 Live2D 모델을 추가하고 플레이어의 `Stage` 렌더러를 교체한다. 스토리 데이터와 저장 시스템은 그대로 유지한다.

## 런타임 검증

`dual_dialogue`와 `dual_narration`은 메시지 창에서 재생한다. `choice`는 조건을 통과한 선택지만 표시한다. `effect`와 `state_gate`는 화면 없이 자동 처리한다. `exit`은 조건에 맞는 다음 장면이나 엔딩으로 이동한다. 선택 시 기존 `resolvePushPull` 계산을 호출하므로 편집기 미리보기와 웹 게임의 결과가 달라지지 않는다.

런타임 테스트는 의미 있는 장면으로의 자동 이동, 선택 사건의 내부 큐 복귀, 마감 실패, 날짜 전환, 엔딩 우선순위, 첫 엔딩 뒤 두 모드 동시 해금, 이전 대화 복원과 layer speaker 해석을 생성 런타임으로 검증한다.
