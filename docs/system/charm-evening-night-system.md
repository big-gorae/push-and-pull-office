# [구현] 매력도와 저녁·밤 페이즈 설계

> 상태: 핵심 자기계발·밤 페이즈와 1주차 일일 콜백 구현 완료. 관심 메모와 추가 끼어들기 사건은 후속 확장
> 연계 시스템: [밀당 시스템 설계](push-pull-system.md), [웹 미연시 플레이어 설계](web-game-player-design.md)

## 결론

퇴근 후 한도윤이 그날의 대화에서 자신만의 힌트를 뽑아 자기계발 계획을 고르는 `저녁·밤 페이즈`를 둔다.

플레이어에게는 매력도, 체력, 외모, 유머, 취향과 피로도를 관리하는 육성 시스템처럼 보인다. 실제로는 다음 원칙을 지킨다.

- `매력도`는 한도윤이 스스로 평가하는 매력 점수이며 히로인의 호감이 아니다.
- 체력·외모·유머·취향은 같은 밀당 행동을 표현하는 추가 선택지를 연다.
- 피로도가 높으면 일부 활동과 추가 표현 선택지를 고를 수 없다.
- 육성값은 일반 사건·엔딩이나 히로인의 의심도·비호감도·증거에 영향을 주지 않는다. 다만 해금 표현에 선언된 `score_bonus`는 유효한 밀당 득점 시 보이는 주도권에 `0~3`의 고정 보너스를 더할 수 있다.
- 추가 선택지는 기본 선택지와 다른 짧은 반응을 볼 수 있지만 같은 밀당 방향·기본 수치·상태 변화로 합류한다. 표현 보너스는 위치·콤보·득점선·숨은 효과를 바꾸지 않는다.
- 게임 안에서는 이 구조를 설명하거나 `가짜`, `무효`, `장식용` 같은 표현을 사용하지 않는다.

따라서 플레이어의 고민은 실제다. 오늘 운동할지, 쉬면서 유머를 올릴지, 피로를 감수하고 특정 표현을 열지는 플레이 감각을 바꾼다. 그러나 그 최적화가 타인의 마음이나 결말을 바꿨다는 인과는 만들지 않는다.

## 플레이 루프

```text
낮의 히로인 대화·행동
→ 한도윤이 관심 힌트로 재해석
→ 퇴근 후 가족 전화·개인 사건
→ 밤 활동 한 가지 선택
→ 매력 프로필과 피로 변화
→ 혼자 다음 대화를 상상하거나 연습
→ 다음 날 같은 기능의 표현 선택지가 늘거나 줄어듦
```

이 루프는 기존 밀당의 정답을 알려 주지 않는다. 힌트는 `서아는 유머 수치가 높으면 넘어온다` 같은 공략 정보가 아니라 그날 들은 말과 한도윤의 해석을 나란히 보여 주는 서사 재료다.

## 플레이어가 관리하는 값

### 매력도

`0~100`의 숫자로 표시한다. 자기계발의 총점처럼 보이지만 다른 관계 상태를 계산하는 입력으로는 사용하지 않는다.

- 화면 이름: `매력도`
- 실제 의미: 한도윤의 자기평가
- 시작 기준값: `30`
- 사용처: 밤 결과, 프로필, 표현 레지스트리의 해금 요구
- 금지: 일반 `conditions`, 사건·엔딩 조건, 히로인 상태와 숨은 결과

매력도는 오직 `manifest.self_development.expressions.*.requires.appeal_gte`를 통해 표현 해금 조건의 일부로 읽는다. 장면이 이 경로를 직접 비교하지 않는다.

매력도는 하위 능력치의 합산값이 아니다. 그래서 쉬거나 유행 영상을 보는 선택은 유머를 올리면서 매력도를 조금 낮출 수 있다. 플레이어는 총점과 필요한 표현 해금 사이에서 고민하게 된다.

### 능력치

각 능력치는 `0~5`이며 표현별 해금치는 레지스트리가 선언한다. 현재 구현된 표현은 `2`단계를 사용하고 `4`단계는 후속 확장에 남긴다.

| 능력치 | 플레이어가 기대하는 효과 | 실제 시스템 효과 |
|---|---|---|
| 체력 | 활동적이고 듬직한 인상 | 적극적인 제안·활동 화법의 표현 선택지 추가 |
| 외모 | 단정하고 매력적인 인상 | 옷차림·자기관리와 관련된 표현 선택지 추가 |
| 유머 | 분위기를 풀고 가까워짐 | 농담·가벼운 받아치기 표현 선택지 추가 |
| 취향 | 공통 관심사와 대화 소재 | 콘텐츠·음식·문화 화제의 표현 선택지 추가 |

능력치는 존중, 공감, 경계 인식처럼 타인을 대하는 태도를 성장시키지 않는다. 한도윤이 관계를 기술과 연출의 문제로 오해한다는 주제와 맞지 않기 때문이다. 상대의 명시적인 요청을 그대로 따르는 `literal` 선택지는 능력치로 잠그거나 강화하지 않는다.

### 피로도

피로도는 `0~6`의 게이지로 표시한다. 활동과 표현은 각자 선언한 한도를 사용한다.

- 운동은 현재 피로 `4` 이하이면서 수행 뒤 `6`을 넘지 않을 때 가능하다.
- 외모 관리는 현재 피로 `5` 이하이면서 수행 뒤 `6`을 넘지 않을 때 가능하다.
- OTT·릴스·수면에는 별도 현재 피로 상한이 없다.
- 모든 양수 피로 활동은 수행 결과가 `6`을 넘으면 잠긴다.
- 표현은 각 expression의 `fatigue_lte`를 만족해야 한다.

피로도 때문에 장면, 히로인, 밀당 방향이나 엔딩이 잠겨서는 안 된다. 피로가 막는 것은 반드시 같은 기능의 기본 선택지가 남아 있는 `표현 변형`뿐이다.

### 후속 확장: 관심 메모

낮 장면의 안정 ID를 출처로 삼는 짧은 메모다.

```text
오늘 떠오른 말
“안전한 동료들과 있을 때는 말이 빨라지고 농담이 많아졌다.”

한도윤의 메모
“가볍게 받아치는 사람이 편한 모양이군.”
```

- 첫 문장은 실제로 관찰된 말이나 행동만 기록한다.
- 두 번째 문장은 한도윤의 해석이며 사실처럼 단정하지 않는다.
- 메모는 관련 밤 활동을 추천하고 해당 능력치 획득량을 `+1` 보너스한다.
- 메모는 발견 후 이틀 밤까지만 추천 효과를 주되 기록 자체는 회차 노트에 남긴다.
- 히로인의 취향을 새로 확정하려면 먼저 인물·세계관 원본에 그 사실이 있어야 한다.

## 저녁·밤의 시간 구조

캠페인의 시간대 열거형은 늘리지 않는다. 제1~16일의 `after_work` 사건 처리가 끝나고 날짜가 바뀌기 직전에 별도 `self_development` 플레이어 페이즈를 한 번 실행한다. 제17일에는 실행하지 않으며 같은 날짜에 중복 실행하지 않는다.

```text
after_work 진입
1. 퇴근 후 스토리 사건
2. 저녁 끼어들기 사건
3. 밤 활동 선택
4. 활동 결과와 혼자만의 해석
5. 날짜 변경과 다음 의미 있는 사건
```

이렇게 하면 기존 이벤트의 `after_work` 배치, 세이브 미리보기, 스케줄러와 에디터를 유지하면서 플레이어에게는 저녁과 밤의 차이를 분명히 연출할 수 있다.

### 1. 퇴근 후 스토리 사건

회식, 야근, 명시적인 경계 대화처럼 기존 `after_work` 사건을 먼저 실행한다. 현재 런타임은 제1~16일이면 사건 뒤 밤 선택을 남긴다. 귀가 불가능한 날을 건너뛰는 `skip_night` 규칙은 후속 리듬 조정 항목이다.

### 2. 저녁 끼어들기 사건

플레이어가 계획을 고르기 전에 발생하는 짧은 대화형 사건이다. 현재는 `common.day_01_parent_pressure`가 구현된 기준 장면이며, 아래 항목은 후속 확장 방향이다.

- 부모의 전화와 결혼 독촉
- 친구나 동료의 안부 메시지
- 배달, 세탁, 밀린 집안일처럼 혼자 사는 생활의 마찰
- 그날 히로인에게서 얻었다고 믿는 관심 메모 정리
- 운동 후 근육통이나 늦잠 같은 이전 활동의 후속 장면

끼어들기 사건은 밤 선택을 빼앗는 벌이 아니다. 활동 목록을 바꾸거나 한 활동을 추천하고, 짧은 서사 뒤 선택권을 돌려준다.

### 3. 밤 활동

하루에 한 가지를 고른다. 레지스트리에는 다섯 활동이 있고 화면에는 수면을 항상 포함해 최대 네 장을 날짜별로 순환 표시한다.

| 활동 | 매력도 | 능력치 | 피로도 | 비고 |
|---|---:|---|---:|---|
| 헬스장 운동 | `+3` | 체력 `+2`, 외모 `+1` | `+2` | 현재 피로 `4` 초과 또는 결과 `6` 초과면 잠김 |
| 옷과 피부 정리 | `+3` | 외모 `+2` | `+1` | 관련 소모품은 연출만 하고 화폐는 두지 않음 |
| OTT 코미디 시청 | `-1` | 유머 `+2`, 취향 `+1` | `-1` | 사용자가 제안한 휴식형 성장의 기준안 |
| 릴스 훑어보기 | `-1` | 유머 `+1`, 취향 `+1` | `-2` | 빠른 회복, 낮은 성장 |
| 일찍 잠들기 | `0` | 없음 | `-4` | 항상 사용 가능한 회복 선택 |

모든 값은 범위에서 제한한다. 능력치가 최대일 때 초과분을 매력도로 바꾸지 않는다. 그런 변환은 최적화가 실제 분기력으로 이어진다는 기대를 지나치게 강화한다.

### 4. 결과와 혼자만의 해석

활동 결과는 짧은 수치 피드백 뒤 대화형 장면으로 마무리한다.

```text
유머 +2   취향 +1   피로 -1   매력도 -1

한도윤
(다음에는 너무 진지하게 받지 말고 한마디 가볍게 던져 볼까.)
```

스토리 모드의 인지 레이어에서는 다음 대화가 잘 풀리는 모습을 상상할 수 있다. 현실 레이어에서는 한도윤이 혼자 영상을 멈춰 가며 문장을 연습하거나 상대의 평범한 말을 반복 재생하는 모습을 보여 준다. 실제로 일어나지 않은 히로인의 대답을 현실 사건처럼 기록하지 않는다.

### 구현된 1주차 활동 회수

밤 결과만 보고 끝나지 않도록 최근 활동 ID를 다음 날 첫 반응에서 한 번 회수한다. 판정은 일반 상태 조건이 아니라 `manifest.self_development.expressions.*.requires.last_activity`를 사용하고, 다섯 활동의 피드백 expression은 모두 `score_bonus: 0`이다.

| 플레이 날짜 | 회수하는 선택 | 구현된 반응 |
|---|---|---|
| 1일차 | 그날 밤 활동 | 활동 결과와 한도윤의 기대·현실 독백 |
| 2일차 | 1일차 밤 | 회의 시작 전 서아가 근육통, 넥타이, OTT 대사, 짧은 영상 또는 이른 출근을 짧게 언급 |
| 3일차 | 2일차 밤 | 업무 외출·휴식 뒤 민경이 활동 흔적을 업무 맥락에서 받아침 |
| 4일차 | 3일차 밤 | 첫 주말 조우 상대가 눈에 보이는 행동이나 공용 화제를 짧게 언급 |
| 5일차 | 4일차 밤 | 두 번째 주말 조우 상대가 같은 활동을 다른 상황에서 짧게 회수 |

각 반응은 활동별 고유 대사와 한도윤의 과해석을 제공한 뒤 기존 사건으로 합류한다. 히로인의 상태, 사건 결과, 주도권, 숨은 수치에는 효과를 쓰지 않는다. 주말 장면은 아직 미확정인 공략 우선 판정과 구체 장소를 고정하지 않도록 상대를 `그날 마주친 동료`로만 표현한다.

## 후속 확장: 힌트가 활동으로 이어지는 규칙

> 아래 관심 메모 레지스트리는 아직 구현하지 않았다. 현재 구현은 낮 대사와 부모 전화가 서사적 힌트를 주고, 플레이어가 밤 활동을 직접 해석해 고르는 단계까지다.

힌트는 장면이 직접 선언한다.

```yaml
self_development_hint:
  id: seo_a_safe_context_humor
  source_node: coworker_banter
  heroine: yoon_seo_a
  stat: humor
  suggested_activities: [watch_comedy, browse_reels]
  expires_after_nights: 2
```

처리 순서는 다음과 같다.

1. 실제 대화나 관찰 노드를 본다.
2. 장면 종료 시 관심 메모를 한 장 추가한다.
3. 저녁 화면에서 가장 최근 메모 한 장을 보여 준다.
4. 연결된 활동에 `오늘 떠오른 말` 표시를 붙인다.
5. 그 활동을 고르면 연결된 능력치에만 `+1` 보너스를 준다.
6. 히로인 상태에는 어떤 효과도 쓰지 않는다.

동시에 여러 메모가 있으면 현재 밀당 흐름의 인물, 최근 발견 순서로 하나만 전면에 보여 준다. 나머지는 노트에서 확인할 수 있다. 인물별 호감 공략표처럼 보이는 별도 화면은 만들지 않는다.

## 능력치로 늘어나는 선택지

### 기능 동등성

추가 선택지는 `더 좋은 선택지`가 아니라 같은 밀당 행동의 다른 표현이다. 모든 해금 선택지는 같은 노드의 상시 기본 선택지 하나를 `equivalent_to`로 가리킨다.

```yaml
- id: ask_plainly
  label: 수정 방향을 지금 더 묻는다
  push_pull: {action: approach, intensity: 12, base_score: 4}
  next: response_join

- id: ask_with_joke
  label: 가벼운 농담을 섞어 수정 방향을 더 묻는다
  self_development:
    expression: humor.light_reply
    equivalent_to: ask_plainly
    converges_at: response_join
  push_pull: {action: approach, intensity: 12, base_score: 4}
  next: joke_flavor_01
```

`ask_with_joke`는 한두 개의 전용 반응 노드를 거쳐 `response_join`으로 합류할 수 있다. 그러나 다음은 `ask_plainly`와 완전히 같아야 한다.

- `push_pull.action`, `intensity`, `base_score`
- 선택과 전용 반응 구간의 상태 효과 합계
- 도달하는 상태 게이트와 사건 시간
- hidden 상태와 엔딩에 남기는 결과

요구 수치와 보이는 보너스는 장면이 아니라 manifest 레지스트리에 둔다.

```yaml
self_development:
  expressions:
    humor.light_reply:
      requires: {appeal_gte: 30, stat: humor, minimum: 2, fatigue_lte: 3}
      score_bonus: 2
```

`score_bonus`만 기능 동등성의 의도된 예외다. 유효한 `score` 또는 `turn` 판정에서 보이는 주도권에 더하며, `wrong`, `outside`, `literal`에서는 0이다.

즉, 유머 선택으로 서아가 잠깐 당황하거나 민경이 농담을 받아 주지 않는 별도 대사는 볼 수 있어도 관계 판정은 달라지지 않는다.

### 항상 남겨야 하는 기본 선택

- 각 기능군에는 조건 없는 기본 선택지를 최소 하나 둔다.
- 피로도와 능력치가 어떤 값이어도 `approach`, `space`, 필요한 경우 `literal`을 수행할 방법이 남아 있어야 한다.
- 추가 선택지가 잠겼다고 사건 진행, 콤보 유지 가능성이나 경계 존중 선택이 사라지면 안 된다.
- 한 화면의 선택지는 최대 네 개로 제한한다. 해금 선택지가 많으면 현재 메모와 최근 사용 능력치를 우선한다.

### 플레이어 표시

현재 낮 선택지는 해금된 표현에 능력치 배지를 붙이고, 잠긴 표현은 숨긴다. 밤 결과에서 새 표현을 별도로 알리는 아래 연출은 후속 확장이다.

```text
새 대화 표현
가볍게 받아치기
```

낮 선택지에서는 작은 `유머` 아이콘만 붙이고 밀당 방향이나 수치 우위를 표시하지 않는다. 아직 열지 못한 표현은 기본적으로 숨긴다. 튜토리얼에서만 잠긴 예시 하나를 보여 주어 능력치가 선택지를 늘린다는 규칙을 가르친다.

## 피로도가 만드는 제약

피로는 계획을 바꾸게 하지만 로맨스 결과를 바꾸지 않는다.

- 활동 비용을 더했을 때 `6`을 넘는 활동은 선택할 수 없다.
- 표현은 각 레지스트리 requirement의 `fatigue_lte`를 넘으면 숨긴다.
- 활동은 각 활동의 `fatigue_lte`와 수행 뒤 최대치 `6`을 함께 검사한다.
- 잠긴 표현에는 항상 기능 동등한 기본 문장이 남는다.
- 하루가 바뀐다고 자동 회복하지 않는다. 회복은 휴식 활동이나 명시된 생활 사건으로만 적용한다.
- 피로 때문에 지각, 업무 실패, 히로인 사건 놓침, 의심도 변화가 자동 발생하지 않는다.

피로가 높을 때는 선택지 외에도 문장을 짧게 바꾸고 화면 호흡을 느리게 할 수 있다. 이 연출 역시 현실 상태 효과를 만들지 않는다.

## 부모 전화와 사적 사건

기존 `common.day_01_parent_pressure`가 저녁 끼어들기 사건의 기준 장면이다. 이후의 부모 전화는 같은 내용을 반복하기보다 자기계발 루프를 흔드는 역할을 맡긴다.

예시:

- 어머니가 요즘 운동은 하느냐고 묻는다. 한도윤은 걱정을 외모 칭찬으로 받아들여 운동을 추천 활동으로 올린다.
- 아버지가 늦게까지 영상만 보지 말라고 말한다. 플레이어는 반발해 OTT를 보거나 일찍 잘 수 있다.
- 부모가 별다른 근거 없이 `너 정도면 괜찮다`고 달랜다. 매력도만 `+1` 되고 능력치는 오르지 않는다.

부모의 말은 객관적인 외모 평가나 히로인의 반응을 보증하지 않는다. 현실 레이어에서는 갈등을 피하려는 가족의 칭찬과 걱정으로 유지한다.

## 17일 캠페인 내부 배치

캠페인 날짜 수와 아래 구간은 제작 정보이며 플레이어에게 일정표로 노출하지 않는다.

| 내부 구간 | 밤 페이즈 역할 | 현재 선택 가능 횟수 |
|---|---|---:|
| 1일 | 부모 전화 뒤 첫 활동 | 1회 |
| 2~5일 | 첫 능력치 2 달성 | 4회 |
| 6~10일 | 능력치 투자와 피로 관리 | 5회 |
| 11~16일 | 해금 표현 확대와 망상 독백 강화 | 6회 |
| 17일 | 최종 사건과 엔딩에 집중 | 없음 |

현재 런타임은 제1~16일에 매일 한 번, 최대 `16회`를 제공한다. 선택일 축소와 `skip_night`는 플레이 리듬 검증 뒤 조정할 후속 항목이다.

## UI 구조

상시 HUD에는 기존 밀당 주도권과 리듬 게이지만 둔다. 자기계발 정보는 밤 장면에서 휴대전화의 `매력 플랜` 화면을 열 때만 표시한다.

```text
┌ 오늘 떠오른 말 ───────────────────────┐
│ “안전한 동료들 앞에서는 농담이 많아졌다.” │
└──────────────────────────────────────┘

매력도 38
체력 2  외모 1  유머 3  취향 1     피로 ■■■□□□

[헬스장 운동]       체력·외모 / 피로 증가
[OTT 코미디 시청]  유머·취향 / 피로 회복  · 추천
[옷과 피부 정리]   외모 / 피로 증가
[일찍 잠들기]      큰 폭으로 피로 회복
```

- 활동 전에는 정확한 증감 수치 대신 방향과 크기만 보여 준다.
- 선택 후에는 실제 증감 수치를 짧게 보여 준다.
- 매력도와 피로도를 히로인 카드 안에 배치하지 않는다.
- `호감`, `성공 확률`, `히로인 선호 보너스`라는 문구를 쓰지 않는다.
- 별도 달력이나 시간대 선택 화면을 만들지 않는다.
- 속마음 모드에서도 `효과 없음`이나 내부 동등성 정보를 공개하지 않는다.

## 데이터 구조

플레이어에게 보이는 값과 진행 기록을 분리한다.

```yaml
visible:
  protagonist:
    self_development:
      appeal: 30
      stats:
        stamina: 0
        appearance: 0
        humor: 0
        taste: 0
      fatigue: 1
progress:
  self_development:
    completed_days: []
    activity_history: []
    last_activity: ""
```

활동과 표현 원본은 장면마다 수치를 복사하지 않고 `story/manifest.yaml`의 `self_development` 단일 레지스트리로 관리한다. 밤 페이즈는 활동 ID만 저장한다.

모든 `visible.protagonist.self_development.*` 경로는 일반 조건식에서 읽지 못하도록 validator 수준에서 금지한다. 대사와 선택지는 제한된 `self_development.expression`만 참조하고, 요구 수치와 점수 보너스는 manifest가 해석한다.

## OOP 경계와 책임

- `SelfDevelopmentProfile`: 매력도·능력치·피로도의 범위가 보장된 값 객체
- `SelfDevelopmentService`: 구버전 상태 보충, 활동 가능 여부, 하루 한 번의 원자적 상태 변경
- `ExpressionEligibilityPolicy`: 표현 requirement와 보이는 점수 보너스 판정
- `NightPhaseCoordinator`: 선택 → 결과 → 날짜 진행의 생명주기
- `resolvePushPull`: 자기계발을 알지 않고 전달받은 `visibleScoreBonus`만 최종 득점에 합산

따라서 활동 규칙, 대사 해금, 시간 진행과 밀당 계산은 서로의 내부 상태를 직접 변경하지 않는다.

## 시스템 반전을 숨기는 제작 규칙

1. 플레이어 문구에서 육성 시스템이 쓸모없거나 가짜라고 말하지 않는다.
2. 매력도가 히로인의 감정이라고 설명하지도 않는다.
3. 활동 직후 히로인의 원격 반응, 우연한 메시지나 호감 상승 연출을 자동으로 붙이지 않는다.
4. 추가 표현을 선택했을 때 전용 대사는 제공하되 더 긍정적인 실제 반응을 보장하지 않는다.
5. 속마음 모드는 혼자 연습한 사실과 과잉 해석을 보여 줄 수 있지만 수치의 내부 무효성을 설명하지 않는다.
6. 엔딩은 기존처럼 의심도·비호감도·증거·최종 행동으로만 판정한다.
7. 외모가 공포나 가해 행동의 원인이라는 해석을 만들지 않는다. 위험의 원인은 경계 침범과 권력 사용이다.

## 검증 계약

현재 다음을 자동 검증한다.

- 자기계발 경로가 일반 조건·효과·전이에 등장하면 실패한다. 표현 requirement만 전용 정책으로 읽는다.
- 모든 해금 선택지는 같은 choice node의 조건 없는 `equivalent_to` 대상을 가진다.
- 해금 선택지와 기준 선택지의 `push_pull`과 `effects`가 다르면 실패한다.
- 전용 반응 분기와 기준 분기가 선언된 `converges_at`에 도달하지 못하면 실패한다.
- 피로 조건 때문에 선택 가능한 옵션이 0개가 되면 실패한다.
- 능력치·피로가 `hidden.heroines.*`, 이벤트 발생 여부나 엔딩 전이를 바꾸면 실패한다.
- 기본 프로필과 최대 자기계발 프로필로 route를 탐색해 모든 선택지를 덮지 못하면 실패한다.
- `night --day <날짜>`로 활동 가능 여부와 차단 사유를 조회하고, `--activity <ID>`를 주면 선택 → 결과 → 종료와 실제 clamp 변화량을 재현한다.
- 하네스의 자기계발 서비스와 밤 코디네이터가 구버전 상태 보충, 제16일 경계, 하루 한 번 제약을 회귀 테스트한다.

관심 메모 출처 일치와 전용 반응을 두 노드 안에 합류시키는 제한은 후속 확장의 검증 항목이다.

1. 상태·활동·표현 레지스트리와 v4 저장 마이그레이션: 구현
2. `after_work` 종료 뒤 밤 페이즈를 호출하는 런타임 훅: 구현
3. 밤 전용 UI, 활동 결과와 이중 의미 독백: 구현
