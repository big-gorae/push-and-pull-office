# [구현] 밀당 UI/UX 설계

## 핵심 결정

정상 플레이에서는 플레이어가 관리할 관계 정보만 보여 주고 제작 메타데이터는 숨긴다.

```text
스토리 모드:  호감도 72 · COMBO x4 · 당기기 ↔ 밀기
```

점수와 위치는 스토리 모드의 관계 리듬으로만 표시한다. 다른 모드에서 라벨이나 의미를 교체하지 않는다.

선택지별 `approach`, `space`, `literal`, 강도, 예상 이동량, 숨은 효과와 결과 산식은 디버깅 모드에서만 표시한다.

## 화면 구조

```text
┌──────────────────────────────────────────────────────────────┐
│                         배경                                  │
│                  현재 발화자 일러스트                        │
│                                                              │
│                                  당기기 ━━━●━━━━ 밀기        │
├──────────────────────────────────────────────────────────────┤
│ 유은솔                                                       │
│ “메일 확인했습니다. 수정본은 내일까지 부탁드릴게요.”         │
│                                               [퀵 메뉴]      │
└──────────────────────────────────────────────────────────────┘
```

- 리듬 막대는 상단의 작은 장식이 아니라 대사창 바로 위 오른쪽에 놓는다.
- 막대는 한눈에 위치를 읽을 만큼 크고 배경과 충분한 명도 대비를 가져야 한다.
- 적정 구간은 기존보다 넓은 시각 영역으로 표현하되 `중앙 적정 범위 안`이라는 문구를 반복하지 않는다.
- 날짜·ACT·캠페인 총일수와 이벤트 타임라인은 이 화면에 강조하지 않는다.
- 배경 위에는 현재 장면의 명시적 `stage`에 배치된 인물만 표시한다. 텍스트 전용 동료는 그리지 않는다.

## 대사

모든 `dialogue`와 `narration`은 단일 `line`만 가진다. 별도 속마음, 해석 보조문단, 인지·현실 쌍은 만들지 않는다. 실제로 소리 내어 하는 혼잣말이 필요하면 일반 `dialogue`로 작성한다.

```text
유은솔
“그 자료는 메일로 보내주세요. 제 자리로 오지 마시고요.”

```

## 선택 화면

선택 화면은 장면을 가리지 않는 선명한 직사각형 목록으로 구성한다.

1. `choice.stimulus`로 선택을 촉발한 말이나 행동을 사실 중심의 한 문장으로 요약한다.
2. 그 아래 `option.label`을 실제 말이나 행동으로 표시한다.
3. `밀기`, `당기기`, `push`, `pull` 같은 제작 판정과 예상 점수는 쓰지 않는다.
4. 미묘한 해석을 고르는 선택도 자연스러운 독백이나 행동 문장으로 쓴다.
5. 같은 행동을 해석만 달리해 중복하지 않는다.

```text
은솔이 “자료는 메일로 보내고 제 자리로 오지 말라”고 요청했다.

┌ 알겠다고 답하고 요청대로 자료만 메일로 보낸다 ┐
└ 퇴근 후 개인 메시지로 이유를 다시 묻는다       ┘
```

디버깅 모드를 켜면 각 버튼 아래에만 `DEBUG · space 12 · 계산 대상 차민경 · 반응 대상 유은솔`처럼 제작 분류를 덧붙일 수 있다. 지원 화법 ID는 제작 검수용 상세 정보에서 확인하되 일반 화면에 성격 정답으로 표시하지 않는다.

## 리듬 피드백

선택 직후에는 인물의 다음 반응을 먼저 보여 준다. 정상 플레이에서 선택 효과 수치나 숨은 상태 변화 팝업을 띄우지 않는다. 표시점, 호감도와 콤보가 바뀌더라도 짧고 조용한 모션만 사용한다.

디버깅 모드에서는 다음 정보를 추가할 수 있다.

- 선택 전후 위치
- 적정 구간 안팎과 활성 득점선
- 콤보·호감도 계산
- 반복 패턴의 숨은 효과

콤보가 끊겼을 때 실패 경고나 정산 모달을 띄우지 않는다. `COMBO xN`이 조용히 사라지고 다음 장면 변화가 결과를 설명한다.

## 날짜 이동과 내비게이션

플레이어용 타임라인 화면은 사용하지 않는다. 런타임은 다음 의미 있는 사건으로 자동 진행하고 날짜가 바뀔 때만 짧은 페이드와 분홍빛 달력·다이얼 전환을 재생한다.

같은 시각에 선택 가능한 사건이 여럿이면 `choice.stimulus`와 실제 행동 선택지로 장면 안에서 고르게 한다. 사건 ID, 우선순위, 마감 계산과 차단 이유는 디버깅 모드에만 둔다.

백로그는 당시의 장면·노드·variant와 speaker ID를 저장한다. locale를 바꿔도 같은 안정 ID에서 문장을 다시 해석한다.

## 디버깅 도구

환경설정의 명시적인 디버깅 모드는 다음을 제공한다.

- 이전 대화로 한 단계 이동하며 전체 상태 스냅샷 복원
- 현재 장면·노드·이벤트·variant ID
- 선택지의 제작용 밀당 분류와 결과
- 선택지의 반응 대상·지원 화법과 별도의 밀당 계산 인물
- 현재 발화자 일러스트의 X/Y/크기 슬라이더

디버깅 모드를 껐을 때 이 정보는 백로그, 토스트, 접근성 문구와 세이브 미리보기에도 새어 나오지 않아야 한다.

## 모션과 접근성

- 일러스트 호흡은 약한 전체 이미지 스케일·위치 변화로 구현하고 움직임 줄이기에서는 정지한다.
- 리듬 막대 변화는 색상만이 아니라 표시점 위치와 텍스트 레이블로 구분한다.
- 선택지는 키보드와 게임패드 방향키로 이동할 수 있고 포커스를 분명히 표시한다.
- 자동 진행 중에도 선택지와 중요한 대사는 충분한 읽기 시간을 보장한다.
- 좁은 화면에서도 직사각형 선택지는 전체 폭으로 쌓고 리듬 막대는 대사창 위에서 읽을 수 있는 최소 폭을 유지한다.

## 런타임 바인딩

```text
visible.heroines.<id>.affection      → 호감도 / 통제 욕구
progress.flags.push_pull.combo        → COMBO / 통제 시도 연쇄
progress.flags.push_pull.position     → 리듬 게이지의 연속 위치
progress.flags.push_pull.target       → 현재 활성 득점선
progress.flags.push_pull.last_action  → 최근 이동 방향과 장면 기록
progress.flags.push_pull.heroine      → 콤보 대상과 인물 이동 판정

option.interaction.target             → 실제 대화 반응 상대
option.interaction.support_styles     → 비노출 지원 화법 저작 태그
option.push_pull.target               → 이 선택의 밀당 계산 인물, 생략 시 루트 히로인
```

`progress.flags.push_pull.target`은 득점선 **방향**이고 `option.push_pull.target`은 **인물 ID**다. 이름이 같아도 서로 대체하지 않는다. `interaction`은 대사 분기와 검수에만 쓰며 점수 계산에는 참여하지 않는다.

내부 계산 순서는 유지한다.

```text
장면 effects 적용
→ 선택 강도만큼 position 증감
→ 적정 구간과 target 방향 판정
→ 득점선 도착 시 target 반전
→ last_action 저장
→ 호감도 점수 계산
→ 반복 패턴 hidden effects 적용
→ 지연 사건 예약
```

## 검수 기준

- 대사 아래에 해석·속마음 보조문단이 남아 있지 않은가?
- 생각이 괄호 발화로 자연스럽게 이어지고 현재 레이어 화자만 보이는가?
- 선택 화면이 직전 말·행동 요약과 구체적인 실제 선택을 제공하는가?
- 제작용 밀기·당기기 분류와 수치가 디버깅 모드 밖에 노출되지 않는가?
- 리듬 막대가 대사창 위 오른쪽에서 크고 선명하며 적정 구간 문구를 반복하지 않는가?
- 플레이어 타임라인과 ACT 화면 없이 장면 선택과 날짜 전환만으로 흐름을 이해하는가?
- 서술에서 `나레이션` 이름표가 나타나지 않는가?
- 작은 화면과 움직임 줄이기에서도 필수 정보가 전달되는가?
