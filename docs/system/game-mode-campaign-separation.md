# [미구현] 게임 모드·캠페인 분리 설계

> 상태 기준: 2026-08-02
> 이전 제안 번호: 1
> 관련 구현: src/player/WebGame.tsx, src/player/playerRuntime.ts, src/player/playerStorage.ts

## 1. 목적

스토리 모드, 속마음 모드, 어나더 스토리를 단순한 화면 전환이 아니라 명시적인 게임 모드로 관리한다. 각 모드는 사용할 캠페인, 시작 레이어, 레이어 전환 정책과 상태 연속성을 직접 선언해야 한다.

이 설계는 다음 문제를 해결한다.

- 현재 ViewMode가 화면에 표시할 레이어와 게임 모드의 의미를 동시에 맡고 있다.
- 어나더 스토리는 해금 표시와 안내 문구만 있고 실제 캠페인을 시작하지 않는다.
- 새 세션이 캠페인 ID를 명시적으로 받지 않고 첫 번째 캠페인을 자동 선택한다.
- 서로 다른 연속성의 상태가 같은 세이브나 프로필에 섞일 위험이 있다.

## 2. 모드와 캠페인의 관계

목표 구조는 다음과 같다.

    base
      campaign: campaign.main
      initial layer: perceived

    truth_view
      campaign: campaign.main
      initial layer: reality

    survivor_view
      campaign: campaign.survivor
      layer policy: fixed reality

스토리 모드와 속마음 모드는 같은 사건과 선택을 서로 다른 레이어로 읽는 모드다. 어나더 스토리는 별도 주인공과 별도 사건을 가진 독립 캠페인이다.

중요한 불변식은 perceived가 언제나 한도윤의 해석이라는 점이다. 어나더 스토리를 추가할 때 perceived를 피해자 시점이나 다른 인물의 속마음으로 재사용하지 않는다.

## 3. 용어와 타입

### GameModeId

- base: 최초 플레이가 사용하는 기본 스토리 모드
- truth_view: 첫 엔딩 이후 해금되는 현실 레이어 중심 모드
- survivor_view: 별도 캠페인을 실행하는 어나더 스토리

### ViewLayer

- perceived: 한도윤이 받아들이는 세계
- reality: 실제로 일어난 세계

### ModeDefinition

모드 레지스트리의 각 항목은 다음 필드를 가진다.

| 필드 | 의미 |
|---|---|
| id | 안정적인 GameModeId |
| campaign_id | 시작할 캠페인의 안정 ID |
| initial_layer | 세션 시작 레이어 |
| layer_policy | fixed 또는 switchable |
| continuity_id | 상태를 공유할 세계선 ID |
| carry_policy | 프로필에서 가져올 정보의 허용 목록 |
| unlock_condition | 잠금 해제 조건 |
| availability | locked, unlocked, coming_soon 중 하나 |

레지스트리는 스토리 메타 데이터에서 선언하고 빌드 시 런타임 JSON으로 컴파일한다. 플레이어 컴포넌트에 캠페인 ID나 해금 조건을 하드코딩하지 않는다.

## 4. 세션과 프로필 경계

세이브 스키마 v4는 최소한 다음 필드를 명시적으로 저장한다.

| 필드 | 저장 이유 |
|---|---|
| game_mode_id | 어느 규칙으로 시작한 플레이인지 식별 |
| campaign_id | 실행 중인 캠페인 식별 |
| continuity_id | 상태 혼합 방지 |
| view_layer | 현재 표시 레이어 |
| layer_policy | 불법 레이어 전환 방지 |

프로필에서는 다음 정보만 모드 사이에 공유한다.

- 해금된 모드
- 달성한 엔딩과 회상
- 접근성 및 플레이어 설정

다음 정보는 continuity_id가 다르면 절대 공유하지 않는다.

- visible과 hidden 상태
- 이벤트 이력과 선택 이력
- 밀당 상태와 증거
- 현재 장면, 노드와 타임라인 진행도

## 5. 실행 흐름

1. 새 게임 화면이 ModeDefinition 목록을 읽는다.
2. 플레이어가 모드를 고르면 game_mode_id를 기준으로 캠페인을 해석한다.
3. 런타임은 campaign_id와 진입 이벤트를 검증한다.
4. 세션은 initial_layer와 layer_policy를 사용해 생성한다.
5. 잠긴 모드나 준비 중인 모드는 세션을 만들지 않는다.
6. 알 수 없는 모드나 캠페인은 첫 번째 캠페인으로 대체하지 않고 복구 가능한 오류를 표시한다.

createCampaignSession은 명시적인 mode definition 또는 campaign ID 없이는 새 세션을 만들지 못하도록 바꾼다.

## 6. 기존 세이브 마이그레이션

v3 세션은 다음 규칙으로 v4에 올린다.

| 기존 값 | 변환 결과 |
|---|---|
| main 캠페인과 perceived | base, campaign.main, perceived |
| main 캠페인과 reality | truth_view, campaign.main, reality |
| 인식할 수 없는 캠페인 | 자동 변환 중지 후 원본 보존 |

마이그레이션은 원본 슬롯을 덮어쓰기 전에 검증하고, 실패하면 해당 세이브를 내보낼 수 있어야 한다.

## 7. UI 규칙

- 새 게임 화면에는 승인된 세 개의 모드 카드만 둔다.
- 속마음 모드와 어나더 스토리는 첫 엔딩 이후 해금한다.
- 준비되지 않은 어나더 스토리는 coming_soon 상태로 표시하고 시작 버튼을 제공하지 않는다.
- 속마음 모드는 별도 캠페인처럼 보이게 하지 않고 같은 사건을 다른 레이어로 보는 경험임을 설명한다.
- 플레이 중 모드를 바꾸는 기능은 제공하지 않는다.
- 디버그 모드에서는 mode, campaign, continuity, layer 값을 모두 확인할 수 있다.

## 8. 빌드·검증 계약

validator는 다음을 검사한다.

- 모든 모드가 존재하는 캠페인을 참조하는가
- 모드 ID, 캠페인 ID와 연속성 ID가 중복되지 않는가
- 캠페인 진입 이벤트가 실제로 도달 가능한가
- fixed 레이어 모드가 런타임에서 다른 레이어로 전환되지 않는가
- 다른 continuity 사이에 상태가 복사되지 않는가
- 준비 중인 모드가 시작 가능한 상태로 노출되지 않는가
- 어나더 스토리가 perceived의 기존 의미를 변경하지 않는가

## 9. 구현 순서

1. 모드 레지스트리와 런타임 스키마 추가
2. 세션 v4와 v3 마이그레이션 추가
3. createCampaignSession의 암묵적 첫 캠페인 선택 제거
4. 새 게임 카드와 모드 시작 흐름을 레지스트리 기반으로 변경
5. 연속성별 상태 격리 테스트 추가
6. 실제 어나더 스토리 캠페인이 확정된 뒤 survivor_view 연결

## 10. 인수 조건

- 세 모드 카드의 상태가 데이터로 결정된다.
- 기본 모드와 속마음 모드는 같은 캠페인에서 서로 다른 시작 레이어를 사용한다.
- 어나더 스토리는 별도 캠페인 없이는 시작되지 않는다.
- 세이브만 보아도 모드, 캠페인, 연속성과 레이어를 복원할 수 있다.
- 캠페인 순서를 바꾸어도 새 게임이 다른 캠페인으로 시작하지 않는다.
- 서로 다른 연속성의 상태가 테스트에서 섞이지 않는다.
- v3 세이브는 결정적으로 변환되거나 원본을 보존한 채 안전하게 거부된다.

## 11. 제외 범위

- 어나더 스토리의 주인공과 개별 사건 작성
- 클라우드 계정과 기기 간 동기화
- perceived와 reality의 서사적 의미 변경
- 플레이 도중 다른 모드로 세션을 변환하는 기능
