# [구현] 시스템 설계 문서 허브

> 마지막 정리: 2026-08-02
> 이 문서는 Love Office의 시스템 설계 문서를 찾고 상태를 판정하는 단일 진입점이다.

## 관리 원칙

1. 신규 시스템 설계는 `docs/system/`에 작성한다.
2. 모든 시스템 설계 문서의 첫 제목은 다음 상태 중 하나로 시작한다.
   - `[구현]`: 현재 런타임·플레이어·에디터에 적용되어 있다.
   - `[부분 구현]`: 기반은 적용됐지만 문서의 핵심 인수 조건 일부가 남아 있다.
   - `[미구현]`: 합의된 설계 또는 제안이며 실행 코드에는 아직 적용되지 않았다.
   - `[폐기]`: 더 이상 구현하지 않으며 다른 문서의 근거로 사용하지 않는다.
3. 제목 상태만 바꾸지 않는다. 구현 상태가 변하면 문서의 현황, 구현 근거, 남은 작업과 이 색인을 함께 갱신한다.
4. 사람의 제품 의도는 `docs/`, 기계가 검증하는 계약은 `story/`, 실제 동작은 `src/`와 `tools/`가 권위 원본이다.
5. 문서와 코드가 다르면 현재 구현 설명에는 코드와 생성 런타임을 우선하고, 문서는 차이를 명시한 뒤 수정한다.
6. 스토리 장면의 사실과 대사는 시스템 문서에 복제하지 않고 안정 ID와 원본 문서만 참조한다.

캐릭터 상호작용 중 반응 화법 축의 내부 명칭은 **MBTI 요소**다. `interaction.target/support_styles`는 실제 반응 상대와 행동으로 관찰되는 지원 화법이고, `push_pull.target`은 한도윤의 리듬 계산 대상이다. 두 필드는 서로를 대신하지 않으며, 명시적인 요청·거절에서는 `literal_respect`와 장면의 현실이 평상시 선호보다 우선한다. 일반 플레이어 화면에는 MBTI/F/T 명칭을 노출하지 않으며, 기계 계약은 `story/SPEC.md`, `story/AI_AUTHORING_RULES.md`와 하네스가 소유한다.

## 현재 자동화 운영 상태

2026-08-02 현재 다음 자동 실행은 일시 중지되어 있다.

- 로컬 pre-push 전체 검증
- GitHub `Love Office CI`
- `main` 필수 `required` 체크와 자동 병합
- Dependabot 보안 업데이트와 정기 버전 업데이트

설계와 검사 코드는 삭제하지 않았다. 필요할 때 `npm run verify`로 수동 일괄 검증할 수 있으며, 자동화를 다시 켤 때는 로컬 훅·GitHub 워크플로·브랜치 규칙·Dependabot 제한을 함께 복원한다.

## 상태 변경 절차

시스템을 구현하기 시작할 때:

1. 문서의 구현 범위와 제외 범위를 먼저 고정한다.
2. 관련 데이터 스키마와 세이브 마이그레이션을 코드보다 먼저 확정한다.
3. 최소 수직 슬라이스와 인수 테스트를 구현한다.
4. 문서의 인수 조건을 모두 만족하면 제목과 이 색인을 `[구현]`으로 변경한다.
5. 일부만 배포하면 `[부분 구현]`을 유지하고 남은 항목을 체크리스트로 남긴다.

문서 상태는 기능의 희망 상태가 아니라 현재 `main`에서 확인 가능한 상태를 나타낸다.
