# [부분 구현] 캐릭터 반응·밀당 학습 피드백 설계

> 상태 기준: 2026-08-02

> 남음: 의미 피드백 이벤트, 1회성 학습 플래그, 흐름·목표 이동 연출과 접근성 인수 조건

## 1. 목적

플레이어가 설명서를 읽지 않아도 선택과 결과를 반복하며 두 가지를 함께 추론하게 만든다.

1. 상대가 지금 감정 인정, 사실 확인, 해결책, 선택권 중 무엇을 먼저 필요로 하는가?
2. 지금 다가가거나 기다리거나 말을 그대로 존중했을 때 한도윤이 계산하는 관계 리듬은 어떻게 움직이는가?

내부 제작 용어와 숫자는 숨기고, 고유 대사·새 정보·후속 콜백과 화면의 리듬 반응만으로 다음 선택을 생각하게 한다.

캐릭터 반응 데이터와 밀당 계산은 구현되어 있지만 일반 플레이의 의미 피드백은 아직 대사와 막대 이동에 집중되어 있다. 따라서 이 문서는 계산식을 바꾸지 않고 추론 순서와 결과 표현을 개선한다.

## 2. 플레이어 경험 원칙

- 선택지는 실제로 말하거나 행동할 내용을 설명한다.
- 일반 화면은 push, pull, 밀기, 당기기, 밀당, 방향과 정확한 수치를 노출하지 않는다.
- 어느 선택이 정답이라고 직접 판정하지 않는다.
- 첫 선택부터 모든 규칙을 설명하지 않고 몇 번의 결과에 걸쳐 한 개씩 체감시킨다.
- 막대는 호감도가 아니라 한도윤이 느끼는 관계 리듬이라는 기존 의미를 유지한다.
- 캐릭터의 실제 감정과 한도윤의 확신을 같은 값으로 취급하지 않는다.
- 지원 화법과 밀당을 독립된 축으로 취급한다. 맞는 화법은 실제 반응·정보·콜백을 바꾸지만 그 자체로 점수나 호감을 만들지 않는다.
- 시스템 설정과 장면 데이터는 F/T나 MBTI 유형을 저장하지 않고, 감정 인정·사실 확인·도움 범위 질문·선택권 반환처럼 장면에서 관찰할 수 있는 행동 선호만 다룬다. F/T는 작가의 임시 메모 이상의 정답표로 사용하지 않는다.
- 현재 상황과 상대의 명시적인 요청·거절이 평상시 성향보다 우선한다.
- 실제 반응은 한도윤의 예상과 조금 어긋날 수 있어야 하며, 플레이어가 다음 장면에서 가설을 수정하게 한다.

## 3. 학습 단계

첫 수직 슬라이스는 구현된 `common.day_02_practical_meeting`을 사용한다. 이 장면은 MBTI 이름을 묻지 않고, 서아가 감정 인정·도움 범위 질문·선택권 반환에 먼저 안도하며 민경이 사실 범위·복구안·역할 합의에 먼저 반응한다는 행동 단서를 비교해 보여 준다.

### 1단계: 현재 필요를 관찰한다

직전 말·표정·업무 맥락에서 “왜 저렇게 반응했지?”라는 가설을 세우게 한다. 선택지는 성격 유형명이 아니라 실제로 할 말과 행동만 보여 준다.

### 2단계: 말의 방식과 타이밍을 함께 고른다

플레이어는 공감할지, 사실과 해결책을 제시할지, 도움 범위를 물을지 정한다. 동시에 지금 다가갈지, 기다릴지, 표현을 문자 그대로 존중할지도 선택한다.

### 3단계: 두 결과를 서로 다른 채널로 본다

지원 화법 결과는 상대의 고유 답변·새 정보·후속 콜백으로, 밀당 결과는 막대 마커의 이동과 연결감으로 보여 준다. 별도 정답 팝업은 띄우지 않는다.

### 4단계: 흐름을 잇되 가설을 수정한다

연속된 선택이 같은 흐름을 만들면 마커 잔상, 짧은 광택 또는 미세한 음향으로 연결감을 표현한다. 실제 반응이 예상과 다르면 실패 판정 대신 다음 선택의 새 단서로 남긴다.

### 5단계: 상황에 따라 편안한 구간이 달라진다

체크포인트나 목표 전환이 생기면 적정 구간이 이동하는 애니메이션을 먼저 보여 준다. 플레이어에게 숨겨진 판정식을 설명하지 않는다.

### 6단계: 명시적 경계가 나오면 성향 판독을 멈춘다

요청·거절·접촉 중단이 명시되면 공감형이나 해결형으로 숨은 뜻을 다시 해석하지 않는다. `literal_respect`가 평상시 선호보다 우선한다. literal reset은 한도윤이 계산하던 흐름의 단절일 뿐, 현실에서 요청을 존중한 행동의 실패나 악영향이 아니다.

각 단계는 프로필의 학습 상태로 한 번만 강조하되, 기능 자체는 재플레이에서도 동일하게 동작한다.

## 4. 피드백 이벤트 모델

밀당 계산 결과인 `PushPullResult`와 대사 분기 결과를 UI가 직접 정답으로 판정하지 않고 다음 의미 이벤트로 변환한다.

| 이벤트 | 일반 플레이 표현 | 디버그 표현 |
|---|---|---|
| position_changed | 마커 이동 | 이전 값, 새 값, 변화량 |
| flow_continued | 짧은 잔상 또는 광택 | 방향과 연속 횟수 |
| checkpoint_reached | 막대의 가벼운 고정 효과 | 체크포인트 ID |
| target_shifted | 적정 구간 이동 | 이전·새 목표 범위 |
| flow_ended | 잔상 소멸 | 종료 이유 |
| literal_reset | 짧은 정지 후 초기화 | 리셋 플래그와 근거 |
| outside_optimal | 색 대비 변화 | 범위와 현재 위치 |
| distinct_response | 고유 대사·새 정보·후속 콜백 | 반응 대상과 사용한 지원 화법 |
| hypothesis_challenged | 예상과 다른 반응을 다음 장면의 단서로 남김 | 상황 예외와 반응 근거 |

일반 플레이용 문구는 중립적으로 작성한다. 예를 들어 관계가 좋아졌다거나 상대가 사랑에 빠졌다는 식으로 숨은 감정을 단정하지 않는다.

## 5. 데이터와 상태

선택지의 두 축은 서로 다른 메타데이터로 기록한다.

```yaml
interaction:
  target: yoon_seo_a
  support_styles: [emotional_validation, ask_before_helping]
push_pull:
  target: cha_min_kyung
  action: approach
  intensity: 12
  base_score: 4
```

`interaction.target`은 실제 화법을 받아 반응하는 현재 `cast`의 인물이다. 비공략 조연도 자신의 `interaction_preferences`가 있으면 대상이 될 수 있다. `push_pull.target`은 밀당 위치·콤보·주도권을 계산할 현재 `cast`의 히로인이며, 생략했을 때만 장면 루트의 기본 히로인을 사용한다. 두 대상은 우연히 같을 수 있지만 서로의 기본값이 아니다. `support_styles`는 저작·검수 메타데이터이고 자체 점수·호감·숨은 수치 효과가 없다.

처음 본 안내 효과를 반복하지 않기 위해 다음과 같은 프로필 상태를 둘 수 있다.

    progress.tutorials.push_pull.marker_seen
    progress.tutorials.push_pull.flow_seen
    progress.tutorials.push_pull.target_shift_seen
    progress.tutorials.push_pull.literal_reset_seen

이 값은 계산 결과에 영향을 주지 않고 표현 강도만 제어한다. 스토리 장면에서 값을 읽거나 쓸 경우에는 반드시 state_contract에 선언하고 변경은 effects에서만 수행한다.

피드백 문구와 접근성 레이블은 안정 키로 로컬라이즈한다. 장면 YAML에 UI 문구를 복사하지 않는다.

## 6. 선택 장면 제작 규칙

첫 학습 장면의 각 선택지는 다음을 만족해야 한다.

- stimulus는 중립적인 현재 상황만 요약한다.
- 선택지 라벨은 구체적인 발언, 행동 또는 해석을 제시한다.
- 모든 선택은 실제로 다른 후속 반응이나 상태 결과를 가진다.
- 결과를 보기 전에 어느 선택이 시스템상 어느 방향인지 알 수 없어야 한다.
- 실패 전용 가짜 선택이나 사실상 같은 결과의 선택을 만들지 않는다.
- 한도윤의 해석과 실제 반응은 각각 perceived와 reality에 모두 존재해야 한다.
- 반응 상대의 `interaction_preferences.support_order`와 `context_overrides`를 확인한다.
- F/T라는 이름 대신 실제 대사에서 관찰되는 안정 `support_styles` ID만 기록한다.
- 맞는 화법은 고유 답변, 새 정보 또는 후속 콜백으로 보상하고 자동 수치 보너스를 주지 않는다.
- 명시적인 요청·거절에는 `literal_respect`를 우선하며, 경계 존중 자체에 의심도·비호감도·증거를 올리지 않는다.
- 다인물 장면에서 반응 상대와 밀당 계산 대상이 다르면 `interaction.target`과 `push_pull.target`을 각각 명시한다.
- `push_pull.target`이 루트 기본 히로인과 다르면 그 인물의 시스템 경로를 `state_contract.writes`에 선언한다.

## 7. 오토·스킵·백로그

- 선택지가 나타나면 오토와 스킵을 멈춘다.
- 처음 보는 핵심 피드백은 최소 표시 시간이 지나기 전 자동으로 넘기지 않는다.
- 이미 본 피드백은 설정에 따라 빠르게 재생할 수 있다.
- 백로그는 대사와 선택 결과 문장만 기록하고 내부 수치와 방향을 기록하지 않는다.
- 이전 대사로 이동하는 디버그 기능이 계산 결과를 중복 적용하지 않아야 한다.

## 8. 접근성과 연출

- 색만으로 상태를 구분하지 않고 마커 모양, 위치와 움직임을 함께 사용한다.
- 모션 감소 설정에서는 잔상과 탄성 애니메이션을 즉시 전환 또는 짧은 페이드로 대체한다.
- 화면 읽기용 알림은 관계가 변했다, 흐름이 이어졌다처럼 중립적으로 표현한다.
- 음향은 보조 수단이며 음소거 상태에서도 모든 정보를 이해할 수 있어야 한다.
- 적정 구간과 마커는 현재 디자인 토큰의 대비 기준을 유지한다.

## 9. 검증 계약

정적 검사와 플레이 테스트는 다음을 확인한다.

- 일반 플레이 문자열에 금지된 제작 용어와 정확한 효과 수치가 없는가
- 숫자, 방향과 판정 근거가 디버그 모드에서만 보이는가
- 모든 선택지가 실제 결과와 후속 대사를 갖는가
- 학습 플래그가 게임 계산에 영향을 주지 않는가
- 스킵, 저장, 불러오기와 이전 대사 이동이 효과를 중복 적용하지 않는가
- 모션 감소와 화면 읽기 환경에서도 피드백을 구분할 수 있는가
- `interaction.target`과 `push_pull.target`이 유효한 현재 `cast` 인물인가
- 반응 대상이 `interaction_preferences`를 가지며 `support_styles`가 안정 ID이고 중복되지 않는가
- 선택한 `push_pull.target`의 모든 시스템 경로가 `state_contract.writes`에 선언됐는가
- 시뮬레이터·탐색기·플레이어가 `interaction.target`이 아니라 `push_pull.target`에만 밀당 결과를 적용하는가
- 지원 화법 메타데이터를 추가하거나 제거해도 같은 `push_pull`·`effects`의 수치 결과는 동일한가
- `common.day_02_practical_meeting`의 네 선택이 모두 도달 가능하고 서로 다른 실제 반응을 갖는가

## 11. 인수 조건

- 구현된 데이터와 수직 슬라이스에서 서아와 민경의 지원 순서가 서로 다른 실제 반응으로 나타난다.
- 반응 대상과 밀당 계산 대상이 달라도 선언된 히로인의 상태만 갱신된다.
- 명시적 요청을 존중한 선택은 자동 수치 보너스를 받지 않지만 숨은 악영향도 만들지 않는다.
- 새 플레이어가 별도 튜토리얼 창 없이 첫 선택들에서 마커 이동, 흐름 연결과 목표 변화의 존재를 볼 수 있다. 이 항목의 전용 연출은 남은 구현 범위다.
- 일반 모드에는 제작 방향과 정확한 수치가 전혀 나타나지 않는다.
- 디버그 모드는 기존 계산 근거를 잃지 않는다.
- 첫 선택 장면의 모든 선택이 대사와 상태에 실제 차이를 만든다.
- 저장 후 재개하거나 백로그를 열어도 효과가 중복되지 않는다.
- 모션 감소와 음소거에서도 결과 구분이 가능하다.
