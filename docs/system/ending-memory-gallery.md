# [미구현] 엔딩·회상 갤러리 설계

> 상태 기준: 2026-08-02
> 이전 제안 번호: 4
> 선행 구현: 엔딩 화면, clearedRoutes, unlockedModes, memories 프로필 필드

## 1. 목적

한 번 본 엔딩과 중요한 장면을 안전하게 다시 볼 수 있는 수집 화면을 제공한다.

현재 엔딩 화면은 경로, 날짜, 이벤트와 선택 수를 보여 주고 모드 해금을 기록한다. 프로필에도 완료 경로와 회상용 문자열 배열이 있지만, 엔딩 도감과 장면 재생 흐름은 구현되어 있지 않다.

## 2. 경험 원칙

- 처음 보는 플레이어에게 잠긴 엔딩의 정체나 조건을 누설하지 않는다.
- 해금 여부는 프로필에 저장하되 제목, 설명과 썸네일 같은 표시 정보는 스토리 레지스트리에서 읽는다.
- 회상 재생은 본편 세이브를 변경하지 않는 읽기 전용 세션이다.
- 서로 다른 캠페인과 연속성의 상태를 합쳐서 장면을 재구성하지 않는다.
- 존재하지 않는 장면을 비슷한 장면으로 자동 대체하지 않는다.

## 3. 콘텐츠 레지스트리

엔딩과 회상은 안정 ID를 가진 메타 데이터로 선언한다.

### EndingDefinition

| 필드 | 의미 |
|---|---|
| ending_id | 변경되지 않는 엔딩 ID |
| campaign_id | 소속 캠페인 |
| route_id | 소속 경로 |
| trigger | 엔딩을 달성했다고 판정할 조건 |
| title_key | 해금 후 표시 제목 |
| description_key | 해금 후 표시 설명 |
| locked_hint_key | 스포일러 없는 잠금 힌트 |
| thumbnail_asset | 선택적인 썸네일 자산 키 |
| order | 갤러리 표시 순서 |

### MemoryDefinition

| 필드 | 의미 |
|---|---|
| memory_id | 변경되지 않는 회상 ID |
| campaign_id | 소속 캠페인 |
| scene_id | 재생할 장면 |
| entry_node_id | 선택적인 시작 노드 |
| unlock_condition | 해금 조건 |
| title_key | 표시 제목 |
| thumbnail_asset | 선택적인 자산 키 |
| replay_state_profile | 재생에 필요한 상태 프로필 |

장면 대사나 번역된 제목을 프로필에 복사하지 않는다. 프로필은 안정 ID와 달성 사실만 저장한다.

## 4. 프로필 기록

### EndingRecord

    ending_id
    route_id
    campaign_id
    game_mode_id
    first_cleared_at
    last_cleared_at
    clear_count
    content_fingerprint

### MemoryRecord

    memory_id
    first_unlocked_at
    replay_snapshot_id
    content_fingerprint

### ReplaySnapshot

회상 장면이 과거 선택에 의존할 때만 최소 상태 스냅샷을 저장한다.

    snapshot_id
    campaign_id
    continuity_id
    scene_id
    entry_node_id
    state_subset
    choice_ids
    selected_variant_ids
    content_fingerprint

전체 세션을 복사하지 않고 재생에 필요한 상태 키만 허용 목록으로 저장한다. 스냅샷을 만들 수 없는 장면은 명시적인 replay_state_profile로 고정된 회상 상태를 사용한다.

## 5. 엔딩 기록 흐름

1. 런타임이 엔딩 조건을 만족한다.
2. ending_id와 현재 캠페인, 경로를 검증한다.
3. 프로필에 최초 달성 시간 또는 재달성 횟수를 기록한다.
4. 엔딩이 해금하는 모드와 회상을 함께 계산한다.
5. 엔딩 화면은 이번에 새로 해금된 항목만 강조한다.
6. 저장이 성공한 뒤에만 갤러리에서 항목을 연다.

화면에 보이는 이벤트 수나 선택 수를 엔딩의 안정 식별자로 사용하지 않는다.

## 6. 갤러리 화면

타이틀 메뉴에서 수집 화면으로 진입한다. 화면은 엔딩과 회상 두 탭으로 나눈다.

### 엔딩 탭

- 해금된 엔딩은 제목, 설명, 최초 달성일과 달성 횟수를 표시한다.
- 잠긴 엔딩은 번호 또는 스포일러 없는 힌트만 표시한다.
- 캠페인 필터는 실제로 해금된 캠페인만 보여 준다.
- 전체 수집률은 숨겨진 비공개 엔딩의 존재를 누설하지 않도록 공개 항목 기준으로 계산한다.

### 회상 탭

- 해금된 장면만 재생할 수 있다.
- 장면은 본편과 같은 단일 대사·연출로 재생한다.

## 7. 회상 재생의 안전 경계

회상은 별도의 read-only 세션으로 실행한다.

- 본편 자동 저장을 만들거나 덮어쓰지 않는다.
- 슬롯 저장, 엔딩 달성, 일반 상태 효과와 프로필 진행을 기록하지 않는다.
- 선택지는 과거 선택을 재현하거나 자유 탐색 정책에 따라 표시하되 결과를 본편에 반영하지 않는다.
- 재생 종료 시 원래 갤러리 위치와 필터로 돌아온다.
- 회상 중 새 번역이나 접근성 설정 변경은 허용한다.

회상에서 새로 발견할 수 있는 정보가 있다면 사전에 허용한 gallery metadata만 기록하며, 서사 상태는 변경하지 않는다.

## 8. 콘텐츠 개정과 호환

- 레지스트리에서 ID가 사라지면 프로필 기록을 삭제하지 않고 unavailable 상태로 보존한다.
- 장면이나 노드 ID가 바뀌면 명시적인 migration alias가 있을 때만 이전한다.
- 스냅샷의 content_fingerprint가 현재 런타임과 다르면 참조 ID를 모두 검증한다.
- 재생을 안전하게 복구할 수 없으면 항목을 잠그지 않고 일시적으로 재생 불가라고 설명한다.
- 원본 기록은 내보내기에 포함한다.

기존 clearedRoutes와 memories 문자열은 알려진 레지스트리 ID와 일치할 때만 새 레코드로 변환한다. 알 수 없는 값은 legacy 항목으로 보존한다.

## 9. 검증 계약

validator와 테스트는 다음을 확인한다.

- 모든 엔딩과 회상 ID가 전역에서 유일한가
- 참조한 캠페인, 경로, 장면과 진입 노드가 존재하는가
- 엔딩 조건과 회상 해금 조건이 선언된 상태만 읽는가
- 회상 스냅샷의 상태 키가 허용 목록 안에 있는가
- 잠금 문구와 썸네일이 엔딩 정체를 누설하지 않는가
- read-only 세션이 본편 세이브와 프로필 진행을 바꾸지 않는가
- 두 레이어 비교가 동일한 안정 노드에서 작동하는가

## 10. 구현 순서

1. 엔딩·회상 레지스트리 스키마와 validator 추가
2. 프로필 레코드와 기존 문자열 배열 마이그레이션 추가
3. 엔딩 달성 트랜잭션과 중복 달성 처리 구현
4. 엔딩 갤러리와 잠금 표시 구현
5. read-only 회상 세션과 원래 화면 복귀 구현
6. 레이어 비교와 콘텐츠 버전 호환 처리 추가

## 11. 인수 조건

- 엔딩을 본 직후 갤러리에 정확히 한 번 해금 기록이 생긴다.
- 같은 엔딩을 다시 보면 최초 달성일은 유지되고 횟수만 증가한다.
- 잠긴 항목은 이름, 이미지와 조건으로 내용을 누설하지 않는다.
- 회상을 끝내도 자동 저장과 슬롯 저장의 바이트 내용이 바뀌지 않는다.
- 첫 엔딩 전에는 reality 비교를 열 수 없다.
- 콘텐츠 개정으로 장면이 사라져도 기존 수집 기록과 내보내기 데이터는 보존된다.

## 12. 제외 범위

- 신규 CG와 썸네일 일러스트 제작
- 임의 장면을 골라 실행하는 개발자용 장면 편집기
- 클라우드 계정 기반 수집 동기화
- 업적, 상점과 유료 해금 시스템
