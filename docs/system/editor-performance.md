# 편집기 성능 점검

## 확인된 병목

장면·대사 편집기의 입력 경로에서 대사 한 글자마다 다음 작업이 함께 실행되고 있었다.

- 전체 씬 객체를 JSON 왕복으로 깊은 복사
- 실행 취소용 전체 씬 스냅샷을 매 입력마다 추가
- 전체 씬의 상태 계약 재계산
- 런타임 원본과 전체 JSON 문자열 비교
- 화면에 보이지 않는 시간·인물·연출·자산 작업공간 재렌더링
- 동일한 이미지 파일을 여러 썸네일에서 Tauri IPC로 중복 로드

인물·시간·구조·자산 편집기에도 자동 저장 여부를 확인하기 위한 전체 JSON 직렬화가 매 입력마다 있었다.

## 적용한 개선

- 대사 편집은 씬 전체가 아니라 변경한 노드와 `nodes` 맵만 얕게 갱신한다.
- 연속 입력은 750ms 동안 하나의 실행 취소 그룹으로 묶는다. 입력이 멈추거나 다른 대사로 이동하면 새 그룹을 시작한다.
- 상태 계약은 장면 설정 탭을 볼 때와 저장 직전에 계산한다.
- 변경 여부는 편집 버전 번호로 추적한다. 전체 JSON 비교는 장면 전환이나 실행 취소처럼 드문 경로에만 남긴다.
- 비활성 작업공간은 마운트 상태와 로컬 초안을 유지하되 다른 작업공간의 입력으로 다시 렌더링하지 않는다.
- 대사 흐름의 각 행을 메모해 바뀐 대사와 선택 상태가 달라진 행만 다시 그린다.
- 이미지 미리보기는 프로젝트 경로와 자산 경로를 키로 공유하며, 같은 파일의 중복 IPC 읽기를 합친다.
- 디코딩된 이미지 캐시는 LRU 32개로 제한해 오래 사용했을 때 메모리가 계속 증가하지 않게 한다.
- 저장 응답에 새 런타임을 적용할 때 전체 프로젝트 payload를 깊은 복사하지 않고 변경된 문서 맵만 갱신한다.
- 씬 자동 저장 중 입력이 추가되면 그 입력을 덮어쓰지 않고 다음 저장 대상으로 유지한다.

## 재현 가능한 입력 경로 벤치마크

```bash
npm run benchmark:editor
```

이 벤치마크는 현재 런타임에서 노드가 가장 많은 씬을 찾아 1,000회 연속 대사 입력을 적용한다. 기존의 전체 씬 복사·매 입력 이력·전체 비교 경로와 새 얕은 갱신·입력 그룹 경로를 같은 데이터로 비교한다.

2026-08-11 로컬 측정에서는 38개 노드 씬 기준 기존 경로 `264.07ms`, 개선 경로 `1.28ms`로 약 `206.1배` 차이가 났다. 이 수치는 React 페인팅이나 Tauri IPC를 포함하지 않는 데이터 갱신 경로의 마이크로 벤치마크이며, 기기별 절대 시간보다 병목 제거 여부를 확인하는 회귀 지표로 사용한다.
