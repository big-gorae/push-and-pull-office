# 오프라인 모바일 대사 제작 동기화

## 1. 목표

휴대폰에서 네트워크가 끊긴 동안에도 대사를 찾아 수정하고, 연결이 돌아오면 변경을
내구성 있는 서버 아웃박스에 올린다. Mac 제작 버전이 다음에 온라인이 되면 변경을
가져와 현재 프로젝트와 비교하고, 안전한 변경만 기존 스토리 저장 파이프라인으로
반영한다.

이 기능의 완료 조건은 다음과 같다.

- 휴대폰에서 설치 가능한 PWA로 동작하고, 첫 온라인 로드 이후 앱 셸과 마지막
  대사 카탈로그를 오프라인에서 다시 열 수 있다.
- 입력 중인 문장과 전송 대기 변경은 IndexedDB에 기록되어 탭 종료나 OS 재시작 뒤에도
  남는다.
- 온라인 복귀는 중복 전송에 안전한 append-only 변경 이벤트를 서버에 보관한다.
- 서버의 모든 레코드는 Sites가 제공하는 인증 사용자 ID로 격리한다.
- Mac은 원격 페이지에 일반 파일시스템 권한을 주지 않는다. 현재 에디터에서 승인된
  프로젝트의 대사 카탈로그 조회와 의미론적 변경 적용 명령만 허용한다.
- Mac 원문이 휴대폰의 기준 문장과 달라졌다면 자동으로 덮어쓰지 않고 충돌로 남긴다.
- 반영은 기존 placeholder, 길이, 전체 스토리 검증, 원자 저장, 런타임 재생성 규칙을
  그대로 통과해야 성공한다.

## 2. 핵심 결정

### 2.1 저장소별 책임

| 저장소 | 책임 | 권위 |
|---|---|---|
| 휴대폰 IndexedDB | 편집 중 초안, 아직 업로드되지 않은 이벤트, 마지막 카탈로그 | 기기 로컬 작업 권위 |
| Sites D1 | 인증 사용자별 변경 이벤트, 처리 결과, Mac이 게시한 최신 카탈로그 | 전달 상태 권위 |
| Mac `story/**/*.yaml` | 실제 게임 원문 | 최종 콘텐츠 권위 |

D1은 YAML의 복제본이 아니다. 동기화가 실패해도 원문은 Mac에 그대로 남으며, 서버
장애가 로컬 제작 파일을 손상시킬 수 없다.

### 2.2 변경 이벤트

각 휴대폰 변경은 다음 불변 필드를 가진다.

```ts
type MobileTextChange = {
  eventId: string;            // UUID, idempotency key
  projectId: string;          // 프로젝트 논리 ID
  localizationKey: string;   // 파일 경로가 아닌 안정 텍스트 키
  locale: string;
  baseValue: string;          // 충돌 화면용 기준 문장
  baseValueHash: string;      // SHA-256
  nextValue: string;
  deviceId: string;
  clientCreatedAt: string;
};
```

클라이언트가 파일 경로나 YAML field path를 보내지 않는 것이 중요하다. Mac은
`localizationKey`를 자체 authoring index로 다시 해석하므로 서버 입력으로 임의 파일을
쓸 수 없다.

### 2.3 의미론적 CAS

파일 revision만 비교하면 같은 YAML의 다른 대사를 고친 경우에도 불필요한 충돌이
생긴다. 모바일 반영은 아래 순서의 field-level compare-and-swap을 사용한다.

1. Mac의 현재 authoring index에서 키의 소유자를 다시 구한다.
2. 현재 문장 hash가 `baseValueHash`와 같으면 현재 파일 revision으로 안전하게 rebase한다.
3. 현재 문장 hash가 새 문장 hash와 같으면 재시도된 이벤트로 보고 성공 처리한다.
4. 둘 다 아니면 `conflict`로 남기고 현재 Mac 문장을 영수증에 포함한다.
5. 안전한 이벤트 전체를 기존 `save_story_text` 단일 트랜잭션에 전달한다.
6. 전체 검증 또는 원자 저장이 실패하면 성공 영수증을 쓰지 않는다.

이 방식은 서로 다른 대사를 양쪽에서 수정한 경우는 병합하면서, 같은 대사를 양쪽에서
수정한 경우만 사람에게 결정을 돌려준다.

## 3. 동기화 상태 머신

휴대폰 이벤트 상태는 다음과 같이 단방향으로 진행한다.

```text
local_draft -> queued_local -> pending_server
                                |       |
                                |       +-> conflict
                                +----------> applied
                                +----------> rejected
```

- 네트워크 오류는 상태 전이가 아니며 같은 `eventId`로 재시도한다.
- 같은 기기에서 같은 키를 다시 고치면 이전 `pending_server` 이벤트는 서버에서
  `superseded`되고 최신 이벤트 하나만 Mac에 전달한다.
- 영수증 적용도 idempotent하며 terminal 상태를 임의로 되돌리지 않는다.
- `applied` 이벤트의 문장을 새 카탈로그 기준으로 승격한 뒤 로컬 초안을 정리한다.

## 4. 온라인 복귀 순서

### 휴대폰

1. IndexedDB 아웃박스를 D1에 idempotent upsert한다.
2. 서버의 최신 Mac 카탈로그를 받는다.
3. 서버 이벤트 상태를 받아 로컬 대기·충돌 표시를 갱신한다.
4. 편집 중인 키는 새 카탈로그로 덮지 않는다.

### Mac 제작 버전의 모바일 동기화 창

1. 현재 승인 프로젝트에서 편집 가능한 대사 카탈로그를 읽어 D1에 게시한다.
2. `pending` 이벤트를 가져온다.
3. 제한된 Tauri 명령으로 의미론적 CAS와 기존 저장 검증을 수행한다.
4. D1에 `applied`, `conflict`, `rejected` 영수증을 기록한다.
5. 반영 후 카탈로그를 다시 게시한다.
6. 창이 열린 동안 온라인 이벤트와 주기적 poll로 위 과정을 반복한다.

## 5. 보안 모델

- Sites 배포는 소유자 전용 접근 정책을 유지한다.
- API는 `oai-authenticated-user-id`가 없는 요청을 거절하고, 모든 조회·변경 쿼리에
  사용자 ID 조건을 포함한다.
- 쓰기 API는 same-origin JSON 요청만 받고 요청 크기, 이벤트 수, 키 형식, 문자열 길이,
  SHA-256 형식을 제한한다.
- D1에는 비밀번호, GitHub 토큰, 파일시스템 경로를 저장하지 않는다.
- 원격 Tauri WebView capability는 정확한 Sites origin과 두 모바일 동기화 명령으로
  한정한다. 기존 `save_scene`, `save_document`, shell, dialog 권한은 주지 않는다.
- Mac 명령은 UI가 넘긴 프로젝트 경로를 받지 않고 현재 `load_project`로 승인된 활성
  루트만 사용한다.
- 서버 침해를 가정해도 임의 경로 쓰기는 불가능하며, 유효한 localization key의 변경도
  현재 문장 hash가 기준과 일치하고 전체 스토리 검증을 통과해야 한다.

## 6. 장애와 복구

- 서비스 워커 업데이트 실패: 기존 앱 셸과 IndexedDB 초안으로 계속 작성한다.
- D1 일시 장애: 이벤트는 `queued_local`로 유지하고 다음 온라인 신호에서 재전송한다.
- 전송 응답 유실: 같은 `eventId` upsert로 중복 생성 없이 복구한다.
- Mac 저장 응답 유실: 새 문장 hash가 현재 값과 같으므로 다음 시도에서 applied 처리한다.
- Mac 외부 변경: 같은 키면 conflict, 다른 키면 의미론적 rebase한다.
- 검증 실패: YAML 교체 전 중단되고 rejected 사유를 휴대폰에서 확인한다.

## 7. 관측과 보존

- 이벤트는 생성·갱신·처리 시간을 기록한다.
- API 응답은 서버 시간을 포함해 휴대폰 시계 오차에 의존하지 않는다.
- 카탈로그는 키별 upsert하고 더 이상 존재하지 않는 키를 generation 단위로 정리한다.
- terminal 이벤트는 UI 진단에 필요한 기간 동안 유지하고, 장기 보존 정리는 별도 정책으로
  추가할 수 있다. 원문 YAML은 이 보존 정책의 영향을 받지 않는다.

## 8. 의도적 비목표

- 휴대폰에서 장면 구조, 효과, 분기, 스테이지를 편집하지 않는다.
- 자동 충돌 병합으로 사람이 쓴 두 문장을 합성하지 않는다.
- 서버를 YAML 원본 저장소나 Git 배포 경로로 사용하지 않는다.
- Mac 제작 버전이 꺼져 있는 동안 로컬 파일이 바뀌었다고 표시하지 않는다. 대신 서버에
  안전하게 대기시키고 다음 Mac 동기화에서 반영한다.
