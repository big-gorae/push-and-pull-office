# 밀당 UI/UX 설계

## 핵심 결정

스토리 모드의 관계 HUD는 `밀당 주도권`, 그 옆의 `COMBO xN`, 아래의 `밀기 ↔ 당기기` 리듬 게이지만 표시한다. 정상적인 미연시의 호감도 하트와 애정 게이지는 의도적으로 넣지 않는다.

```text
스토리 모드  밀당 주도권 72  ·  COMBO x4             당기기 ──[● 적정 범위 ]── 밀기
원문 모드  통제 욕구 72    ·  통제 시도 연쇄 x4    접근 시도 ──[●]── 거리 둠
```

숫자는 그대로 두고 라벨만 바꾼다. 플레이어가 올린 점수가 처음부터 사랑이 아니라 통제였다는 사실을 저장 데이터 자체로 보여 주기 위해서다.

## UX 목표

- 선택 전에 관리할 정보는 `현재 위치`, `활성 득점선`, `현재 콤보`, `남은 사건 기회`뿐이다.
- 선택지에는 `다가가기`, `여백`, `literal` 같은 제작 태그나 예상 점수를 노출하지 않는다.
- 콤보 성공은 즉시 시청각적으로 보상하되, 현실의 부정적 변화는 장면 안에서 함께 보인다.
- 기다리기도 다음 장면을 바꾸는 능동적인 선택으로 느껴져야 한다.
- 원문 모드는 새 화면이 아니라 이미 플레이한 화면의 의미가 교체되는 경험이어야 한다.

## 화면 구조

```text
┌ Day 07 · 화요일 · 퇴근 후 ───────── 밀당 주도권 72 · COMBO x4 ┐
│                    당기기 ────[ 적정 범위 ●──── ]──── 밀기     │
│                                                                  │
│                         장면과 인물                              │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│ 윤서아                                                           │
│ “메일 확인했습니다. 수정본은 내일까지 부탁드릴게요.”             │
│ 한도윤 해석: 내가 물러설 차례라는 신호다.                        │
├──────────────────────────────────────────────────────────────────┤
│ [확인했다고 답하고 내일 수정본을 보낸다]                         │
│ [수정 방향을 지금 더 묻는다]                                     │
└──────────────────────────────────────────────────────────────────┘
```

### 상단 HUD

왼쪽에는 날짜와 시간대만 둔다. 오른쪽에는 주도권 숫자와 콤보 배수를 한 줄로 붙이고, 그 아래에 밀기·당기기 리듬 게이지를 둔다.

- 주도권은 숫자와 얇은 진행선으로 표현한다.
- 콤보는 `x1~x5` 텍스트 배지만 사용한다.
- 리듬 게이지는 왼쪽 `당기기`, 오른쪽 `밀기`의 연속 위치를 사용하되 내부 수치는 표시하지 않는다.
- 막대 중앙의 `-40~40`을 적정 범위로 은은하게 강조한다.
- 적정 범위 양쪽의 득점선 중 현재 목표 하나만 작은 표식으로 강조한다.
- 표시점은 한 선택마다 전체 길이의 약 `4~8%`만 이동한다. 장면 효과가 강해도 한 번에 반대편으로 넘어가지 않는다.
- 표시점은 누적된 밀기·당기기 상태를 나타내며 상대의 감정 상태를 뜻하지 않는다.
- 히로인별 호감도 카드나 여러 상태 아이콘은 만들지 않는다.
- 콤보가 없을 때는 `COMBO` 자리 자체를 숨겨 HUD가 조용해지게 한다.

선택 전에는 현재 표시점과 활성 득점선을 보여 준다. 선택을 확정하면 인물의 반응 뒤에 표시점이 조금 이동하고, 적정 범위·이동 방향·득점선 도착 여부를 차례로 판정한다.

### 장면

화면의 대부분은 배경과 인물에 사용한다. 점수가 올라도 인물 위에 하트, 음표나 호감 파티클을 뿌리지 않는다. 보상은 HUD와 짧은 화면 리듬으로 제한한다.

한도윤의 해석은 대사창 아래 한 줄로 나타난다. 원문 모드에서는 같은 자리가 인물의 실제 의도나 속마음으로 교체된다.

### 선택지

선택지는 한 화면에 두 개를 기본으로 한다.

- 첫 줄에는 객관적으로 수행할 행동만 쓴다.
- 시스템 태그와 수치 예상치는 숨긴다.
- 현재 콤보를 이어 가는 선택이라고 별도로 강조하지 않는다.
- 명시적 요청이나 거절이 있을 때만 말을 그대로 따르는 선택을 제공한다.
- 객관적 행동이 같은 선택지를 해석만 다르게 중복해서 만들지 않는다.

## 상호작용 흐름

```text
대사 확인
→ 선택지 등장
→ 행동 선택
→ 인물의 즉시 반응
→ 리듬 게이지 표시점이 한 단계 이동
→ 적정 범위와 활성 득점선 판정
→ 콤보 또는 방향 전환 보너스 판정
→ 주도권 점수 짧게 합산
→ 다음 시간대에 지연 결과
```

선택 직후 숫자를 먼저 띄우지 않는다. 상대의 반응을 먼저 보여 준 뒤 HUD가 계산되어야 플레이어가 `반응을 끌어냈기 때문에 점수를 받았다`고 느낀다.

### 성공한 콤보

```text
밀당 성공  +4
COMBO x3  +8
64 → 76
```

이 계산은 HUD 아래에 1초 정도 나타난 뒤 사라진다. 전체 결과 모달이나 별도 정산 화면은 사용하지 않는다.

### 득점선 도착

적정 범위의 활성 득점선에 표시점이 닿으면 해당 표식이 짧게 점등되고 `턴 보너스`를 합산한다. 이어서 반대편 득점선이 활성화된다.

```text
적정 당기기 도착  +6
다음 득점선       밀기 →
```

다음 행동부터 반대 방향으로 이동해야 콤보가 이어진다. 같은 방향을 한 번 더 선택하면 표시점은 계속 이동하지만 점수를 주지 않는다.

### 끊긴 콤보

콤보가 끊겼을 때 실패 경고를 띄우지 않는다.

- `COMBO xN`이 조용히 사라진다.
- 주도권 기본 점수만 반영하거나 점수를 주지 않는다.
- 다음 장면 변화로 왜 흐름이 끊겼는지 보여 준다.

`literal` 선택에는 `선행`, `정답` 같은 도덕 점수를 주지 않는다. 한도윤 시점에서는 명백한 점수 손해로 보여야 한다.

표시점이 적정 범위를 벗어나면 콤보 배지를 숨기고 막대의 바깥 구간만 약하게 강조한다. 중앙으로 돌아오는 동안은 위치만 회복하며 점수를 합산하지 않는다.

## 콤보 연출 단계

콤보는 배수 하나만 표시하지만 단계별 감각은 달라진다.

| 단계 | 표면 보상 | 장면의 불길한 변화 |
|---|---|---|
| x1 | 주도권 숫자가 짧게 상승 | 없음 |
| x2 | 배지와 짧은 효과음 | 답변이 조금 짧아짐 |
| x3 | 숫자 합산이 두 박자로 등장 | 주변 직원이 프레임에 남음 |
| x4 | HUD가 잠시 밝아짐 | 연락이 공식 채널로 이동 |
| x5 | 가장 강한 점수·사운드 보상 | 대사와 따뜻한 UI가 명백하게 어긋남 |

화면 흔들림과 번쩍임은 x4~x5에서도 약하게 유지한다. 공포 연출보다 플레이어가 보상에 취하도록 만드는 것이 먼저다.

## 지연 결과 UX

여백 두기의 보상은 다음 시간대에 나타난다.

```text
어제 선택: 대화를 끝내고 수정본을 기다림
오늘 결과: 윤서아에게 업무 메일 도착
한도윤 해석: 내가 물러나자 먼저 다가왔다.
```

이전 선택을 작은 아이콘이나 로그 코드로 표시하지 않는다. 다음 장면의 첫 문장과 한도윤 독백이 자연스럽게 기억을 환기한다.

플레이어가 다른 히로인 사건을 고르면 현재 콤보가 끊긴다는 사실은 선택 확인창을 띄우지 않고 HUD의 xN이 흐려지는 미리보기로 알린다. 선택을 취소하면 원래 밝기로 돌아온다.

## 원문 모드 전환

원문 모드는 같은 레이아웃과 같은 점수를 유지한다.

### 교체되는 것

- `밀당 주도권` → `통제 욕구`
- `COMBO` → `통제 시도 연쇄`
- `당기기 / 밀기` → `접근 시도 / 거리 둠`
- 한도윤의 해석 → 실제 인물의 의도와 속마음
- 따뜻한 강조색 → 차가운 기록 강조색
- `밀당 성공` → `반복 패턴 확인`

### 유지되는 것

- 날짜와 시간
- 점수와 콤보 숫자
- 리듬 게이지의 위치
- 선택했던 객관적 행동
- 인물과 배경의 기본 배치
- 저장된 사건 순서

화면을 완전히 새로 만들지 않아야 `내가 올린 바로 그 숫자`가 다른 뜻이었다는 충격이 생긴다.

## 원문 모드 재생 예시

```text
스토리 모드
밀당 성공 · COMBO x3
“내가 물러나자 먼저 연락해 왔다.”

원문 모드
반복 패턴 확인 · 통제 시도 연쇄 x3
“대면 접촉을 피하려고 업무 메일로만 보냈다.”
```

원문 모드에는 의심도·비호감도 숫자를 상시 노출하지 않는다. 필요한 경우 장면 종료 기록에서 `동료에게 공유`, `공식 채널로 전환`, `증거 보존` 같은 실제 사건만 보여 준다. 숫자 공개보다 의미 재해석이 우선이다.

## 내비게이션

### 시간 선택

점심과 퇴근 후의 선택 가능 사건만 화면 하단에 두 개까지 표시한다.

```text
점심
[서아에게 수정본 전달]
[민경과 일정 검토]
```

각 카드에는 제목과 `오늘까지`, `내일까지` 같은 자연어 마감만 표시한다. 확률, 예상 점수와 추천 배지는 넣지 않는다.

다른 히로인을 선택해 콤보가 끊길 때는 현재 콤보 배지만 흐려져 기회비용을 알려 준다.

### 백로그

스토리 모드 백로그는 다음 세 줄을 한 묶음으로 저장한다.

1. 실제로 들은 대사
2. 선택한 객관적 행동
3. 한도윤의 해석

원문 모드에서는 3번만 실제 의도와 결과로 교체한다. 동일한 행동 기록을 유지해 서술 트릭이 아니라 해석의 문제였음을 보장한다.

## 상태별 카피

| 상황 | 스토리 모드 | 원문 모드 |
|---|---|---|
| 콤보 시작 | 밀당의 흐름을 잡았다 | 첫 통제 시도 기록 |
| 콤보 유지 | 예상대로 다시 반응했다 | 반복 패턴 확인 |
| 콤보 x5 | 완전히 내 페이스다 | 대응·기록 연결 |
| 콤보 종료 | 흐름을 잠시 놓쳤다 | 반복 중단 |
| 다른 인물 선택 | 새로운 가능성을 본다 | 관찰 대상 변경 |

카피는 한도윤을 칭찬하는 시스템 문구처럼 시작하지만, 직접적인 폭력이나 경계 침범 방법을 재현 가능한 공략 팁으로 설명하지 않는다.

## 모션과 사운드

- 주도권 상승: 숫자가 현재 값에서 결과 값으로 짧게 카운트한다.
- 콤보 상승: 배지가 한 번만 확대됐다가 원래 크기로 돌아온다.
- 콤보 종료: 흔들림 없이 투명해진 뒤 제거한다.
- 원문 전환: 화면 전체를 뒤집지 않고 텍스트 라벨과 강조색이 순서대로 교체된다.
- x4~x5: 보상 사운드 뒤에 사무실 알림음이나 키보드 소리를 겹쳐 현실의 흔적을 남긴다.

필수 정보는 모션이나 색상에만 의존하지 않는다. 배수, 라벨과 결과 문구를 항상 함께 제공한다.

## 반응형 구성

### 넓은 화면

- 배경과 인물은 화면의 약 70%를 사용한다.
- 대사와 선택지는 하단 30%에 겹쳐 배치한다.
- HUD는 한 줄로 유지한다.

### 좁은 화면

- 상단에 날짜, 그 아래 주도권과 콤보를 두 줄로 재배치한다.
- 인물은 상반신 중심으로 자른다.
- 선택지는 세로 전체 폭 버튼으로 배치한다.
- 점수 합산은 HUD 아래 한 줄로만 표시한다.

## 접근성

- 선택지는 키보드와 게임패드 방향키로 이동할 수 있어야 한다.
- 포커스는 시각적으로 명확하게 표시한다.
- 콤보 변화는 `COMBO x3`처럼 텍스트로 읽히게 한다.
- 리듬 게이지는 `현재: 당기기 쪽, 적정 범위 안`, `다음 득점선: 밀기`처럼 현재 위치와 목표를 텍스트로 함께 읽히게 한다.
- 모션 감소 설정에서는 확대·카운트 애니메이션을 즉시 값 교체로 바꾼다.
- 스토리 모드와 원문 모드의 차이는 색상뿐 아니라 라벨과 문장으로 구분한다.
- 자동 진행 중에도 선택지와 중요한 실제 대사는 충분한 읽기 시간을 보장한다.

## 런타임 바인딩

```text
visible.heroines.<id>.initiative      → 밀당 주도권 / 통제 욕구
progress.flags.push_pull.combo        → COMBO / 통제 시도 연쇄
progress.flags.push_pull.position     → 리듬 게이지의 연속 위치
progress.flags.push_pull.target       → 현재 활성 득점선
progress.flags.push_pull.last_action  → 최근 이동 방향과 장면 기록
progress.flags.push_pull.heroine      → 콤보 대상과 인물 이동 판정
```

선택 결과의 표시 순서는 다음으로 고정한다.

```text
장면 effects 적용
→ 선택 강도만큼 position 증감
→ 적정 범위와 target 방향 판정
→ 득점선 도착 시 target 반전
→ last_action 저장
→ 주도권 점수 계산
→ 반복 패턴 hidden effects 적용
→ 지연 사건 예약
→ UI 피드백 재생
```

## 검수 기준

- 첫 플레이어가 호감도 없이도 목표가 주도권 상승임을 이해하는가
- 플레이어가 리듬 게이지만 보고 현재 당기기·밀기 정도와 적정 범위 안팎을 즉시 구분하는가
- 표시점이 한 선택마다 충분히 작게 이동해 누적 상태처럼 느껴지는가
- 활성 득점선에 도착한 뒤 반대 방향으로 전환해야 한다는 사실을 한 번의 왕복 안에 학습하는가
- 콤보 규칙을 별도 튜토리얼 표 없이 두 번의 선택 안에 학습하는가
- x3 이상에서 점수 보상과 장면의 불길함을 동시에 느끼는가
- `literal`을 골랐을 때 시스템 오류가 아니라 의도적인 점수 포기로 이해하는가
- 다른 히로인 선택이 콤보를 끊는다는 사실을 확인창 없이 알아차리는가
- 원문 모드에서 같은 점수의 라벨 변경만으로 의미가 뒤집히는가
- 작은 화면과 모션 감소 설정에서도 모든 정보가 전달되는가
